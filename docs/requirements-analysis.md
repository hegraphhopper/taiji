# 需求分析

## 1. 背景

电科太极自投研发项目（平台基金、创新基金）逐年增多，申报书由各项目组独立编写，存在同一方向重复立项、跨组近似投入、同期并行申报等问题。现有流程依赖人工比对，缺少结构化申报、可解释的重复度分析、趋势归因与决策辅助。

本系统面向所内基金项目管理，提供“申报书结构化 → 重复度分析 → 趋势归因 → 投入态势 → 辅助决策 → 审批治理”的闭环。

## 2. 用户与权限

| 角色 | 代码 | 主要职责 | 数据范围 |
|------|------|----------|----------|
| 系统管理员 | `ADMIN` | 用户/角色/项目组/技术方向/系统参数/审计/分析配置 | 全所 |
| 基金办 | `PMO` | 全所项目查看、形式审查、立项/驳回/终止、分析运行、趋势/投入、决策、报告导出 | 全所 |
| 项目组用户 | `GROUP_USER` | 维护本组项目与申报书、上传解析、提交/撤回、执行/结项、预检、查看本组分析 | 本组 |
| 评审专家 | `EXPERT` | 查看全部评审中项目及本组非草稿项目、重复度报告、提交评审 | 评审中 + 本组 |

接口与页面双重校验；数据范围在服务层强制，越权返回 403 并写审计。

## 3. 核心业务流程

```text
项目组创建项目/填写结构化申报书 → 上传 docx/pdf/md 解析回填
  → 提交 → PMO 形式审查 → 专家评审（评分/结论）
  → PMO 立项 → 项目组开始执行 → 结项
驳回后可修改并重新提交；新一轮评审重新计数。
```

## 4. 功能需求

- FR-01 组织、用户、角色、技术方向、系统参数与审计。
- FR-02 项目与申报书结构化维护、附件上传解析、状态机。
- FR-03 混合重复度分析：字段权重、等级阈值、Top-K 相似对、可解释片段、可选大模型解释。
- FR-04 重复度趋势、四类归因、热力图与下钻。
- FR-05 投入态势与风险敞口。
- FR-06 新项目预检、规则建议、决策记录、Word/Excel 报告。
- FR-07 专家评审、审批轨迹、待办中心。
- FR-08 演示数据、数据库备份、文档与部署。

## 5. 非功能需求

| 编号 | 要求 |
|------|------|
| NFR-01 | 本地 H2 零依赖启动；MySQL 8 生产部署 |
| NFR-02 | 300 项目分析 ≤ 5s（本地算法） |
| NFR-03 | JWT + 角色/数据范围；密码 BCrypt；审计脱敏 |
| NFR-04 | 大模型失败自动降级，不阻断主流程 |
| NFR-05 | JDK 8 / Maven 3.5+ / Node 18+ / Chrome/Edge 近两版 |
| NFR-06 | 全部配置环境变量化；无默认生产密钥 |
| NFR-07 | 分析快照留存，趋势可复算 |

## 6. 范围边界

- 不做：OA/财务/统一身份对接、扫描件 OCR、可视化流程设计器、财务凭证/工时、原生 App、模型训练/微调。
- 大模型仅通过 OpenAI 兼容接口调用，作为解释层时 `localWeight=100 / llmWeight=0` 不改变总分。

## 7. 验收口径

- 四角色权限矩阵、组数据隔离、越权 403。
- 申报书解析回填目标/内容/关键技术。
- 重复度分数、四类归因、趋势≥12 个月。
- 完整审批流与驳回重提。
- 预检/决策记录/Word/Excel 报告与页面一致。
- `mvn test`、`npm run build` 通过。

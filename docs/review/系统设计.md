## 1 设计目标与约束

### 1.1 设计目标

- 以最小依赖完成可评审演示：本地 H2 文件库 + 一键脚本启动，无需安装 MySQL。
- 重复度分析结果可解释、可复算、可追溯：项目对级明细与项目级快照同时留存。
- 外部大模型为可选增强：关闭、超时、报错时不影响主流程与趋势口径。
- 四类角色与数据范围在服务层强制生效，前后端权限口径同源。
- 配置全部环境变量化，生产部署不依赖代码改动。

### 1.2 技术约束

| 约束 | 说明 |
|------|------|
| JDK 8 | 编译与运行目标版本，不使用高版本语法 |
| Spring Boot 2.7.18 | 后端框架，Spring Security 5.7 |
| MyBatis-Plus 3.5.3.2 | 数据访问，逻辑删除字段 `deleted` |
| Flyway | 数据库版本管理，迁移脚本 V1–V7 |
| H2 2.1 文件模式 | 演示数据库，`MODE=MySQL` |
| MySQL 8 | 生产数据库 |
| Vue 3 + Vite 5 | 前端框架与构建 |
| Element Plus / ECharts | 组件库与图表 |
| Node 18+ | 前端构建环境 |

## 2 总体架构

### 2.1 逻辑分层

```text
+-----------------------------------------------------------+
|  表现层  Vue 3 SPA（Element Plus + ECharts + Pinia）        |
|  路由守卫 / 菜单权限 / 统一 Axios 拦截 / 错误与空态          |
+---------------------------|-------------------------------+
                            | HTTPS / JSON / JWT
+---------------------------v-------------------------------+
|  接口层  Spring MVC Controller（/api/v1）                  |
|  参数校验 / @PreAuthorize 角色校验 / 统一响应 Result        |
+---------------------------|-------------------------------+
|  应用层  Service（事务边界、业务规则、数据范围、审计注解）    |
+---------------------------|-------------------------------+
|  领域与算法层  分析引擎 / 归因 / 评分 / 决策规则 / 报告生成   |
+---------------------------|-------------------------------+
|  数据访问层  MyBatis-Plus Mapper + 逻辑删除 + 分页插件       |
+---------------------------|-------------------------------+
|  存储层  H2（demo，文件）/ MySQL 8（prod）+ 附件文件系统     |
+-----------------------------------------------------------+
```

分层依赖单向向下；Controller 不直接访问 Mapper；算法类为无状态纯计算，便于单元测试。

### 2.3 技术选型

| 领域 | 选型 | 理由 | 替代方案与代价 |
|------|------|------|----------------|
| 后端框架 | Spring Boot 2.7 | JDK 8 兼容、生态成熟、Security/Validation/OpenAPI 齐备 | 升级 3.x 需 JDK 17，超出交付环境 |
| 数据访问 | MyBatis-Plus | 简单 CRUD 与分页，逻辑删除统一 | JPA 学习成本低但复杂查询可控性差 |
| 数据库 | H2 + MySQL 8 | H2 保障零依赖演示，MySQL 满足生产 | 仅 MySQL 需评审环境装库 |
| 迁移 | Flyway | 版本化、可重复、H2/MySQL 兼容 | 手工 SQL 易漂移 |
| 前端 | Vue 3 + TS + Vite | 组合式 API、类型约束、构建快 | React 亦可，但团队栈为 Vue |
| 图表 | ECharts | 趋势、堆叠、热力图开箱可用 | 自绘成本高 |
| 鉴权 | JWT | 无状态、前后端分离友好 | Session 需共享存储 |
| 大模型 | OpenAI 兼容 HTTP | 可替换供应商、默认关闭 | 专用 SDK 绑定供应商 |

### 2.4 横切设计

| 关注点 | 实现 |
|--------|------|
| 统一响应 | `Result{code,message,data,traceId}`，成功 code=0 |
| 异常处理 | 全局异常处理器映射 ErrorCode → HTTP 状态；不返回堆栈与 SQL |
| 认证 | JWT 过滤器解析 token，注入 SecurityContext |
| 授权 | 接口 `@PreAuthorize` + 服务层数据范围断言 |
| 审计 | `@Audit` 注解 + AOP 切面，记录操作人、动作、资源、IP、结果、耗时，敏感字段脱敏 |
| 参数校验 | Bean Validation + 服务层业务校验 |
| 分页 | MyBatis-Plus 分页插件，统一 PageResult |
| 时间 | 统一 Asia/Shanghai，Jackson 输出 `yyyy-MM-dd HH:mm:ss` |
| 日志 | 运行日志 + LLM 调用日志（仅元数据，不含 Prompt/Key） |

### 3.2 认证与权限模块

- 登录流程：校验用户名 → 校验锁定状态 → BCrypt 比对 → 失败计数/锁定 → 生成 JWT → 返回 token、角色、权限点。
- JWT 载荷包含用户 ID、用户名、角色、项目组；过滤器解析后写入 SecurityContext。
- 权限目录 `PermissionCatalog` 定义 22 个权限点及允许角色；前端登录后获取权限点控制菜单与按钮。
- 数据范围由 `ProjectAccessService` 与 `DataScopeService` 统一断言，列表查询在 SQL 层加范围条件。

时序（登录）：

```text
浏览器 → AuthController.login → AuthService
  → UserMapper 查询用户
  → 校验锁定/启用/BCrypt
  → JwtTokenProvider 生成 token
  → 审计切面记录 LOGIN
  → 返回 token + roles + permissions
```

### 3.3 项目与申报模块

- 项目主数据与五类结构化内容分表存储，保存内容时整体覆盖。
- 状态机由 `ProjectWorkflowService` 集中实现，每次流转写 `project_approval_log`。
- 提交校验在服务层执行；更新使用 `version` 字段做乐观并发控制。
- 详情聚合：项目 + 内容 + 附件 + 评审 + 审批轨迹 + 最近快照与项目对。

时序（提交）：

```text
项目组 → POST /projects/{id}/actions(SUBMIT)
  → ProjectAccessService.assertCanEdit
  → 校验状态 DRAFT/REJECTED
  → validateForSubmit（预算/日期/目标/内容/节点）
  → 写 submit_time、状态 SUBMITTED、审批轨迹
  → 审计 PROJECT_SUBMIT
```

### 3.4 附件与解析模块

- 上传校验链：扩展名 → 大小 → 数量 → 文件签名 → 落盘。
- 存储使用随机文件名，数据库保存原文件名、相对路径、大小、类型。
- 解析：docx 使用 POI、pdf 使用 PDFBox、txt/md 直接读取；失败记录 `parse_message`。
- 章节解析按标题正则识别目标/内容/关键技术/节点/考核指标，无标题时全文作为内容候选。
- 回填接口返回章节候选，前端勾选后调用保存申报内容。

### 3.5 重复度分析模块

- `AnalysisRunService` 负责编排：并发保护（两个 AtomicBoolean）、运行记录、失败清理。
- `AnalysisExecutor` 负责纯计算：加载语料 → 构建向量 → 两两打分 → Top-K 并集 → 可选 LLM → 快照。
- 计算阶段不开启事务；`AnalysisResultWriter` 在同一事务内落库项目对与快照。
- 单项目分析仅保留与目标项目相关的项目对；全量分析覆盖全部非草稿项目。
- 运行状态：RUNNING → SUCCESS / FAILED；失败按 run_id 删除明细。

时序（全量运行）：

```text
PMO → POST /analysis/runs
  → 获取 heavyRunning 锁
  → 检查无 RUNNING 运行
  → 写入 analysis_run(RUNNING)
  → AnalysisExecutor.execute（计算）
  → AnalysisResultWriter.persist（事务落库）
  → 更新 SUCCESS（耗时/项目数/对数/llmUsed）
  → 审计 ANALYSIS_RUN_CREATE
```

### 3.6 趋势与归因模块

- 数据源为 `duplicate_snapshot`，按分析日期聚合；同一项目同一时间粒度只取最新快照。
- 趋势指标：分析项目数、平均最高分、平均 Top-K 分、高风险项目数、项目对战与唯一对数、高风险对数、环比。
- 归因以项目视角统计，跨组对双方各计一次；四类计数之和与项目对数一致。
- 热力图支持项目组×月份与技术方向×项目组，可切换平均分或高风险项目数。
- 下钻条件由前端写入 URL，后端按时间与等级过滤项目清单。

### 3.7 投入态势模块

- 统计范围：APPROVED、IN_PROGRESS、COMPLETED 项目。
- 指标：总预算、项目数、在研/结项数、平均预算、已分析数、平均最高分、高风险数、风险敞口。
- 风险敞口 = Σ(项目预算 × 项目最高重复度 / 100)；高风险敞口单独统计。
- 多维分布：年度、基金类型、项目组、技术方向；Top 高风险项目。
- 导出 CSV/Excel，包含口径说明。

### 3.8 辅助决策模块

- 预检复用分析引擎的 Top-K 能力，取 Top-1 作为风险分与等级。
- 规则按优先级升序匹配首个启用规则；支持分数区间、关系、同组条件；未命中回退 EXPLAIN。
- 预计重复投入 = 预算 × 风险分 / 100，保留 2 位。
- 专家建议按技术方向与历史评审负载排序。
- 决策记录保存项目、运行、风险分、等级、建议、相似项目、金额、操作人。
- 报告使用 Apache POI 生成 Word/Excel，内容含项目信息、结论、相似项目、重复/差异点、模型复核与口径说明。

### 3.9 待办与系统管理模块

- 待办：ADMIN/PMO 看待审查与待立项；GROUP_USER 看本组草稿与被驳回；EXPERT 看本轮未评审的 REVIEWING 项目。
- 系统管理：用户增改与角色分配、项目组与技术方向树、系统参数、审计查询与导出。
- 被引用的项目组/技术方向禁止删除，返回业务错误。

### 4.4 索引与约束

- 唯一约束：项目编码、用户登录名、角色编码、项目组编码、技术方向编码、配置版本、用户角色组合。
- 高频查询索引：项目（组+状态）、项目（技术方向）、项目（提交时间）、项目对（运行+项目+总分）、快照（项目+日期）、快照（组+日期）、审计（时间/用户/动作）。
- 逻辑删除仅用于项目、用户、项目组、技术方向、决策记录；审计日志与快照不删除。
- 时间统一 DATETIME，日期统一 DATE；金额 DECIMAL(14,2)；分数 DECIMAL(5,2)。

### 4.6 备份与恢复设计

- H2：停止写入后打包 `./data/funddb.*`，备份文件需记录校验和与解压后大小。
- MySQL：使用 `mysqldump` 全量导出，配合 Flyway 版本表确认结构版本。
- 恢复：停止应用 → 还原数据文件或导入 SQL → 启动 → 校验项目数、快照数与审计数。

## 5 接口设计

### 5.1 接口约定

- 基础路径 `/api/v1`；除登录、健康检查外均需 `Authorization: Bearer <JWT>`。
- 请求与响应均为 `application/json; charset=UTF-8`；文件上传为 `multipart/form-data`。
- 统一响应：`{code, message, data, traceId}`；成功 `code=0`。
- 分页参数：`page`（从 1 开始）、`size`（默认 10，最大 100）；返回 `records/total/page/size`。
- 时间格式 `yyyy-MM-dd HH:mm:ss`；日期 `yyyy-MM-dd`。
- 失败响应不返回堆栈、SQL、密钥与内部路径。

## 6 关键算法与规则设计

### 6.1 文本处理

1. 归一化：全角转半角、去除 HTML 标签、统一空白、去除控制字符。
2. 中文切分：术语词典最长匹配优先，命中词权重 3；其余汉字去停用字后生成 2-gram，权重 1。
3. 英文与数字：匹配 `[a-z0-9_]{2,}` 整词，权重 1。
4. 停用词与纯标点过滤。
5. 语料级 TF-IDF：`tf = 1 + ln(加权词频)`，`idf = ln((N+1)/(df+1)) + 1`，向量 L2 归一化。

说明：TF-IDF 必须对整批语料一次性构建，禁止每对项目单独构建，否则相似度不可比。

### 6.2 五维打分

| 维度 | 公式 | 缺失处理 |
|------|------|----------|
| 项目目标 | 余弦相似度 × 100 | 任一方无文本记缺失 |
| 研制内容 | 余弦相似度 × 100 | 同上 |
| 关键技术 | 余弦相似度 × 100 | 同上 |
| 节点计划 | (名称 Jaccard × 0.6 + 时间区间重叠 × 0.4) × 100 | 任一方无节点记缺失 |
| 技术标签 | Jaccard × 100 | 任一方无标签记缺失 |

时间区间重叠：取各自全部节点计划的最小开始与最大结束，按交集/并集计算。

### 6.3 本地分融合

```text
本地分 = Σ(维度分 × 维度权重) / Σ(有效维度权重)
```

默认权重：目标 15、研制内容 35、关键技术 35、节点计划 5、技术标签 10。缺失维度不参与分子与分母；结果保留 2 位并截断到 0–100。

### 6.4 等级判定

```text
score >= high            → HIGH
medium <= score < high   → MEDIUM
low <= score < medium    → LOW
score < low              → NONE
```

默认 high=80、medium=60、low=40；阈值必须满足 `0 < low < medium < high <= 100`。

### 6.5 Top-K 截断

1. 计算全部项目对的本地分，低于 low 阈值的丢弃。
2. 以本地分为准，为每个项目保留前 K 个对手。
3. 取所有项目 Top-K 的并集作为落库集合。
4. 大模型结果不参与入选范围，只影响总分。

### 6.6 归因判定

```text
if 同组: SELF_GROUP
elif 跨组:
    时间差 = |submit_time(A) - submit_time(B)|（缺失回退 created_at）
    if 时间差 <= simultaneous_days: SIMULTANEOUS
    else: 较早方为 A_EARLIER / B_EARLIER
    若时间完全相等：项目 ID 小者为在先
```

落库保存关系、中性方向与在先项目 ID；展示时按查看项目翻译为 OUR_EARLIER / PEER_EARLIER，SELF_GROUP 与 SIMULTANEOUS 原样展示。

### 6.7 快照与趋势

```text
max_score      = 涉及该项目的项目对中的最高总分
avg_top_score  = 涉及该项目的 Top-K 项目对总分均值
high_pair_count= 涉及该项目且等级为 HIGH 的对数
归因计数        = 按关系与方向统计涉及该项目的对数
risk_exposure  = 项目预算 × max_score / 100
```

趋势按 `analysis_date` 所在月/季/年聚合；同一项目在同一时间粒度内只取最新一次运行，跨粒度保留历史，避免重复计数。

### 6.8 风险敞口

```text
风险敞口 = Σ(项目预算 × 项目最高重复度 / 100)
预计重复投入 = 项目预算 × Top-1 重复度 / 100
```

仅统计已批准、进行中、已结项项目；未分析项目单列且不计入平均分分母。

### 6.9 预检规则匹配

- 规则按优先级升序，首个满足“分数区间 + 归因条件 + 同组条件”的启用规则生效。
- 分数区间右开：`min_score <= score < max_score`，`max_score=100` 时包含 100。
- 未命中任何规则时回退 EXPLAIN（人工判断）。
- 默认规则：≥90 终止；80–90 同组合并；80–90 他组在先合并；60–100 补充说明；<60 通过。

### 6.10 大模型复核

调用条件：环境变量启用且分析配置开启，且本地分进入 Top-N。

请求：OpenAI 兼容 `POST {baseUrl}/chat/completions`，`temperature=0`，`response_format=json_object`，系统提示“只输出 JSON”。

输出字段：`semanticScore`、`overlaps`、`differences`、`suggestion`、`reason`；严格 JSON 校验，非法即失败。

降级链：未配置 → DISABLED；超时 → TIMEOUT；HTTP 非 2xx → HTTP_ERROR；非法 JSON → INVALID。任一失败仅记录日志，沿用本地结果。

缓存：key 为 `sha256(projectId|peerId|textHash|configVersion)`，TTL 24 小时，容量 5000。

熔断：单次运行连续失败 3 次后停止调用，下一次运行重新计数。

解释层模式：`localWeight=100 / llmWeight=0` 时总分不变，仅展示模型重复点、差异点与理由。

### 6.11 融合公式

```text
总分 = (本地权重 × 本地分 + 模型权重 × 模型分) / (本地权重 + 模型权重)
```

模型分缺失时总分等于本地分；权重和必须大于 0；结果保留 2 位并截断到 0–100。

### 6.12 立项 PASS 门禁

统计项目全部轮次中 `result=PASS` 的不同专家数，同一专家多轮 PASS 只计 1 人；达到 `review.requiredPassCount`（默认 2）才允许 REVIEWING → APPROVED。

## 8 安全设计

### 8.1 认证

- 密码 BCrypt 哈希；登录失败计数与锁定；禁用用户 token 立即失效。
- JWT 默认有效期 8 小时；密钥来自 `JWT_SECRET`，生产必填。
- 登出清理服务端会话上下文并写审计。

### 8.2 授权

- 接口级 `@PreAuthorize` 校验角色。
- 服务层 `ProjectAccessService` / `DataScopeService` 校验数据范围。
- 前端菜单与按钮仅做体验控制，不作为安全边界。

### 8.3 数据范围

| 角色 | 可见范围 | 可编辑范围 |
|------|----------|------------|
| ADMIN | 全部 | 全部（按动作） |
| PMO | 全部 | 审查、立项、驳回、终止 |
| GROUP_USER | 本组 | 本组 DRAFT/REJECTED |
| EXPERT | REVIEWING + 本组非 DRAFT | 仅提交评审 |

### 8.4 上传安全

- 扩展名白名单：docx、pdf、txt、md。
- 大小限制 20MB，数量限制 10 个。
- 文件签名校验（magic number）。
- 文件名清洗，去除路径分隔符与 `..`，防路径穿越。
- 存储使用随机文件名，原文件名仅存数据库。

### 8.5 审计与脱敏

- 所有写操作使用 `@Audit` 注解；审计详情 JSON 截断至 1900 字符。
- 敏感字段名包含 password、token、secret、apikey、credential、authorization 时替换为 `***`。
- 审计查询与导出仅 ADMIN。

### 8.6 密钥与配置

- `JWT_SECRET`、`DB_PASSWORD`、`LLM_API_KEY`、`ADMIN_INIT_PASSWORD` 仅从环境变量读取。
- 日志不输出 Prompt、项目正文、API Key、Token。
- 演示环境使用开发密钥，生产必须替换。

## 10 设计取舍与风险

### 10.1 关键取舍

| 取舍 | 选择 | 代价 | 替代方案 |
|------|------|------|----------|
| 演示数据库 | H2 文件模式 | 与 MySQL 存在少量方言差异 | 仅 MySQL，增加评审环境依赖 |
| 大模型定位 | 默认关闭、可选增强 | 演示默认无模型理由 | 默认开启，增加不稳定性与成本 |
| 趋势口径 | 同一粒度取最新快照 | 历史细粒度变化被折叠 | 全量留存，查询复杂且易重复计数 |
| 归因落库 | 存中性事实，展示时翻译 | 展示层多一次转换 | 按视角落库，产生双份数据 |
| 审批流程 | 固定状态机 | 不支持自定义流程 | 流程引擎，超出本期范围 |
| Top-K 截断 | 本地分决定入选 | 模型可能错过低本地分高语义项目 | 全量模型调用，成本高 |
| 附件解析 | 仅文本层 | 不支持扫描件 | 接入 OCR，增加依赖 |

### 10.2 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 大模型不可用 | 预检缺少模型理由 | 自动降级，页面标注 llmUsed=false |
| 语料规模增长 | 全量分析耗时上升 | Top-K 截断、向量批量构建、性能门禁 |
| 演示环境端口冲突 | 无法启动 | stop-demo 脚本与端口配置 |
| H2 文件锁 | 双进程启动失败 | 启动前检查与文档提示 |
| 数据范围遗漏 | 越权风险 | 服务层统一断言 + 越权用例 |
| 截图/UI 漂移 | 评审材料与系统不一致 | 交付前按当前版本重拍截图 |
| 教学/演示数据被误认为真实 | 评审误解 | 全部 `DEMO-` 前缀与文档声明 |

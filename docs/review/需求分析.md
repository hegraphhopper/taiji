## 1 引言

### 1.1 编写目的

本文档面向电科太极自投研发项目（平台基金、创新基金）的重复投入治理场景，定义系统的用户角色、业务流程、功能需求、非功能需求与验收标准，作为系统设计、开发实现、测试验证与项目评审的共同依据。

### 1.2 范围

系统覆盖“结构化申报 → 重复度分析 → 趋势归因 → 投入态势 → 辅助决策 → 审批治理”的完整闭环，包含 Web 前端、后端服务、数据库迁移、演示数据与部署脚本。

本期不包含：OA/财务/统一身份对接、扫描件 OCR、可视化流程设计器、财务凭证与工时、移动端原生应用、大模型训练与微调。

### 1.3 术语与缩写

| 术语 | 说明 |
|------|------|
| 重复度 | 两个项目在申报内容上的相似程度，取值 0–100 |
| 本地分 | 仅由本地文本算法计算出的重复度 |
| 总分 | 本地分与大模型语义分按权重融合后的重复度 |
| 高风险对 | 等级为 HIGH 的项目对 |
| 归因 | 重复来源分类：本组内部、他组在先、我方在先、同期并行 |
| 同期并行 | 跨组且申报时间差不超过同期窗口（默认 30 天） |
| 解释层模式 | 本地权重 100、大模型权重 0，总分不变，仅展示模型理由 |
| PASS 门禁 | 立项前要求的专家 PASS 人数阈值 |
| 快照 | 某次分析在某分析日期上生成的项目级汇总记录 |

## 2 项目背景与目标

### 2.1 业务背景

电科太极通过平台基金、创新基金等自投资金支持各业务部门技术创新，申报项目逐年累积。立项书、研制任务书、结项报告分散在不同系统，评审依赖专家逐份翻阅，存在三类问题：

1. 看不见：项目目标、研制内容、关键技术、节点计划没有统一结构化沉淀，跨部门检索困难。
2. 算不清：技术点撞车、研制内容重复只能到立项会上发现，重复投入无法量化，预算浪费不可见。
3. 管不住：缺少重复度随时间变化的趋势与归因，无法判断问题出在本组重复申报还是跨组撞车。

### 2.2 建设目标

- 让项目管理人员在立项前看到新项目与存量项目的重复程度、重复点与差异点。
- 让管理人员看到重复度随时间的变化趋势，并按四类归因定位治理对象。
- 让技术创新投入可量化呈现，包括重复投入风险敞口。
- 让申报、评审、立项、结项过程可追溯，形成可复用的数据资产。

### 2.3 成功指标

| 指标 | 目标值 | 验证方式 |
|------|--------|----------|
| 分析覆盖 | 全部非草稿项目可一键分析，输出项目级与项目对级结果 | 全量运行后核对项目数 |
| 分析时延 | 300 项目全量分析 ≤ 5s（本地算法，不含外部模型） | 性能用例 |
| 分析时延 | 单项目分析 ≤ 2s | 性能用例 |
| 归因可解释 | 每个高风险项目可下钻到相似项目、重复点与差异点 | 页面走查 |
| 趋势可用 | ≥ 12 个月趋势点与四类归因构成 | 趋势页 |
| 决策闭环 | 预检输出等级、建议动作、预计重复投入，可导出报告 | 预检与导出让走查 |
| 数据可信 | 指标可由项目与快照明细复算；写操作有审计 | 抽查复算 |
| 聚合性能 | 60 项目 × 24 月趋势聚合 ≤ 500ms | 性能用例 |

### 3.3 数据范围规则

- 列表查询、详情查询、导出、预检在服务层强制过滤，前端隐藏仅作体验优化，不作为安全边界。
- GROUP_USER 仅能创建、查看、编辑本组项目；跨组访问返回 403。
- EXPERT 可查看所有 REVIEWING 项目，以及本组非 DRAFT 项目；不可编辑项目内容。
- PMO/ADMIN 全所可见；删除类操作仅 ADMIN 或 PMO 按权限点执行。
- 项目状态为 DRAFT/REJECTED 时才允许编辑申报内容与附件；SUBMITTED 及之后只读。
- 项目组用户只能撤回本人提交的项目。

### 3.4 认证与审计约束

- 本地账号 + JWT，无状态鉴权；密码 BCrypt 存储。
- 连续登录失败 5 次锁定 10 分钟；禁用用户的旧 token 立即失效。
- 所有写操作通过审计切面记录操作人、动作、资源、IP、结果、耗时；密码、Token、密钥、Authorization 字段脱敏。
- 审计日志仅 ADMIN 可查询与导出，界面不提供删除。

## 4 业务流程与用例分析

### 4.1 端到端主流程

```text
项目组创建草稿
  → 填写目标/研制内容/关键技术/节点计划/预算/成员
  → 上传申报书附件（解析并回填）
  → 申报前重复度预检（可选）
  → 提交申报
  → 基金办形式审查
  → 专家评审（评分 + 意见 + 结论）
  → 立项 / 驳回（驳回可修改后重提）
  → 在研执行 / 结项 / 终止
  → 结项材料作为存量数据参与后续查重
```

### 4.2 申报与审批流程

```text
DRAFT --SUBMIT--> SUBMITTED --ACCEPT--> REVIEWING --APPROVE--> APPROVED
  ^                   |                     |  \
  |                   |--WITHDRAW--> DRAFT  |   --REJECT--> REJECTED --SUBMIT--> SUBMITTED
  |                                          |
  +------------------------------------------+
APPROVED --START--> IN_PROGRESS --COMPLETE--> COMPLETED
APPROVED / IN_PROGRESS --TERMINATE--> TERMINATED
```

规则：

- SUBMIT 校验预算大于 0、起止日期完整且结束不早于开始、至少 1 条目标/1 条研制内容/1 条节点。
- ACCEPT 将评审轮次加 1；REJECT 必须填写意见；TERMINATE 必须填写意见。
- APPROVE 要求全部轮次中不同专家 PASS 人数达到 `review.requiredPassCount`（默认 2）。
- 每轮每位专家只能提交一次评审，提交后不可修改。
- 所有状态流转写入审批轨迹，并同步写审计日志。

### 4.3 重复度分析闭环

```text
触发分析（全量 / 单项目 / 申报前预检）
  → 非草稿项目构建分析语料
  → 文本清洗、分词、术语加权、运行级 TF-IDF
  → 五维相似度（目标/研制内容/关键技术/节点计划/技术标签）
  → 加权归一得到本地分
  → Top-K 并集截断
  → 可选大模型复核（Top-N）
  → 权重融合得到总分与等级
  → 落库项目对与项目快照
  → 趋势聚合与归因构成
  → 下钻到项目对与重复/差异文本
```

### 4.4 归因判定口径

| 归因 | 判定 | 管理含义 |
|------|------|----------|
| SELF_GROUP 本组内部 | 两项目同属一个项目组 | 本组内部重复申报 |
| PEER_EARLIER 他组在先 | 跨组且对方提交更早 | 我方撞他组，需说明差异或合并 |
| OUR_EARLIER 我方在先 | 跨组且我方提交更早 | 他方撞我方，需保护已有投入 |
| SIMULTANEOUS 同期并行 | 跨组且提交时间差 ≤ 同期窗口 | 并行立项风险，需协调归口 |

- 判定以提交时间（submit_time）为准，缺失时回退创建时间（created_at）。
- 提交时间完全相等的跨组项目按项目编号小者为在先，不归为同期。
- 同组项目一律归为本组内部，不再判断同期。
- 落库保存中性事实（方向 + 在先项目 ID），展示时按查看视角翻译为我方/他方。

### 4.6 关键用例说明

UC-05 上传附件并解析回填：

- 前置：项目处于 DRAFT/REJECTED，附件数量小于 10，文件为 docx/pdf/txt/md 且不超过 20MB。
- 主流程：选择文件 → 校验扩展名、大小、文件签名 → 落盘 → 解析正文 → 识别“项目目标/研制内容/关键技术/节点计划/考核指标”章节 → 返回章节预览 → 用户勾选后回填 → 保存申报内容。
- 备选：未识别到章节标题时，将全文作为研制内容候选并给出提示。
- 异常：文件类型不支持、超过 20MB、超过 10 个、解析失败（展示失败原因，可重试）。

UC-14 全量分析运行：

- 前置：无其他全量/单项目分析正在运行。
- 主流程：选择全量 → 记录 RUNNING → 加载全部非草稿项目 → 两两打分 → Top-K 并集 → 可选模型复核 → 落库项目对与快照 → 记录 SUCCESS、耗时、项目数、对数。
- 备选：管理员可指定分析日期做历史回填，仅统计该日期前已提交项目，且不回写项目当前分数。
- 异常：重复触发返回 409；运行失败标记 FAILED 并按 run_id 清理明细。

UC-22 辅助决策预检：

- 前置：选择项目或输入文本，GROUP_USER 只能预检本组项目。
- 主流程：调用分析预检取 Top-K → 取 Top-1 作为风险分 → 按规则匹配建议动作 → 计算预计重复投入 → 推荐专家 → 返回风险等级、相似项目、重复/差异点、建议。
- 备选：保存为决策记录，可导出 Word/Excel。
- 异常：文本全空返回参数错误；无相似项目时按低风险处理。

## 5 功能需求

### 5.1 认证与权限

**FR-01 本地账号登录**：用户名 + 密码登录，成功后返回 token、角色与权限点。
规则：BCrypt 校验；成功清空失败计数并记录最后登录时间。
异常：凭据错误返回 40101；连续失败 5 次锁定 10 分钟返回 40102；禁用账号返回 40105。
验收：四类演示账号均可登录并进入对应工作台。

**FR-02 登出**：清除服务端登录上下文并写审计。
验收：登出后原 token 访问业务接口返回 401。

**FR-03 修改密码**：校验原密码，新密码至少 8 位且同时包含字母与数字。
异常：原密码错误返回 40104；弱密码返回 40012。
验收：修改后旧密码不可登录，新密码可登录。

**FR-04 接口级角色鉴权**：按接口声明角色校验，未认证返回 401，无权限返回 403 统一 JSON。
验收：EXPERT 访问分析运行接口返回 403。

**FR-05 服务层数据范围**：项目、附件、分析、趋势、投入、决策、导出均按角色数据范围过滤。
验收：GROUP_USER 通过接口枚举他组项目返回 403 或空结果。

**FR-06 统一错误响应**：返回 `{code,message,data,traceId}`，HTTP 状态与错误码一致，不返回堆栈与 SQL。
验收：任意异常响应不含敏感信息。

### 5.2 项目与申报书

**FR-07 项目主数据**：名称、编码、基金类型、项目组、负责人、技术方向、预算、起止日期、摘要、预期成果。
规则：编码全局唯一，支持 `TJJH-{年}-{4 位}` 自动生成；预算必须大于 0。
异常：编码重复返回 40020。
验收：新建后列表与详情字段一致。

**FR-08 结构化申报内容**：项目目标、研制内容、关键技术（含难度）、节点计划（含权重）、项目成员（角色/人月）。
规则：支持多条与排序；保存为整体覆盖。
验收：五类内容可增删改并持久化。

**FR-09 提交申报**：DRAFT/REJECTED 可提交，执行完整性校验。
异常：预算、日期、目标、内容、节点缺失时返回 400/40010。
验收：缺项无法提交并提示具体原因。

**FR-10 撤回申报**：仅提交人可撤回 SUBMITTED 项目。
异常：非提交人返回 403；状态不符返回 40010。
验收：撤回后回到 DRAFT，审批轨迹新增一条记录。

**FR-11 形式审查**：PMO/ADMIN 对 SUBMITTED 项目执行 ACCEPT 或 REJECT。
规则：ACCEPT 进入 REVIEWING 且评审轮次加 1；REJECT 必须填写意见。
验收：两种动作均写入审批轨迹。

**FR-12 专家评审**：EXPERT 对 REVIEWING 项目提交评分（0–100）、意见、结论（PASS/REJECT/REVISE）。
规则：每轮每人一次；提交后不可修改；仅本轮未评项目出现在评审任务。
验收：重复提交被拒绝；评审记录在详情页可见。

**FR-13 立项门禁**：REVIEWING 项目在去重专家 PASS 数达到配置阈值后才允许 APPROVE。
异常：未达标返回 400 并提示当前人数。
验收：阈值改为 3 后，2 人 PASS 无法立项。

**FR-14 驳回与重提**：SUBMITTED/REVIEWING 可驳回，意见必填；驳回后可修改并重新提交。
验收：驳回意见在审批轨迹展示；重提后新一轮评审可再次打分。

**FR-15 执行与结项**：APPROVED 可 START，IN_PROGRESS 可 COMPLETE。
验收：状态流转正确且写审计。

**FR-16 终止项目**：APPROVED/IN_PROGRESS 可 TERMINATE，意见必填。
验收：未填意见返回 400；终止后不可再执行。

### 5.3 附件管理

**FR-17 附件上传**：支持 docx/pdf/txt/md，单文件 ≤20MB，每项目 ≤10 个。
异常：类型不支持 40030；超限 40031；数量超限 40032。
验收：四类文件均可上传，非法类型被拒。

**FR-18 附件解析**：上传后自动提取正文，识别目标/内容/关键技术/节点/考核指标章节。
规则：无章节标题时全文作为研制内容候选；失败可见原因并可重试。
验收：样例 docx 可解析出至少三类章节。

**FR-19 章节预览与回填**：返回章节候选，用户确认后写入结构化字段。
验收：回填后申报内容与预览一致。

**FR-20 附件下载与删除**：下载保留原始文件名；删除需编辑权限并写审计。
验收：删除后列表与存储均不可再访问。

### 5.4 重复度分析

**FR-21 全量分析**：对全部非草稿项目两两分析并落库。
规则：同一时刻仅允许一个重任务运行。
异常：重复触发 409。
验收：60 项目演示数据全量分析成功并生成快照。

**FR-22 单项目分析**：仅计算目标项目与其余项目的项目对。
验收：其他项目结果不受影响。

**FR-23 文本处理**：全角转半角、HTML 去标签、控制符清洗；中文 2-gram + 术语最长匹配加权 3；英文/数字整词；运行级 TF-IDF 余弦。
验收：同义术语项目得分高于无关项目（抽样验证）。

**FR-24 五维打分**：目标、研制内容、关键技术为余弦 ×100；节点计划为名称 Jaccard×0.6 + 时间区间重叠×0.4；技术标签为 Jaccard×100。
规则：任一方该维度无内容时该维度记为缺失并跳过。
验收：五维分数均可单独复算。

**FR-25 加权与等级**：`本地分 = Σ(维度分×权重)/Σ(有效维度权重)`，默认权重 15/35/35/5/10。
规则：等级阈值默认 low 40、medium 60、high 80，可配置。
验收：修改权重后重新分析，分数按新权重变化。

**FR-26 申报前预检**：对项目或文本取 Top-K 相似项目，输出分维度得分与重复/差异点。
验收：草稿项目预检不落项目对，仅返回结果。

**FR-27 分析配置**：字段权重、阈值、Top-K、同期窗口、本地/模型权重、模型开关、候选数、超时。
规则：版本自增，历史可查，仅 ADMIN 可改。
验收：保存后版本 +1，历史保留旧配置。

**FR-28 大模型复核（可选）**：仅对本地分 Top-N 调用，输出语义分、重复点、差异点、理由；失败自动降级。
规则：`总分 = (本地权重×本地分 + 模型权重×模型分)/(权重和)`；解释层模式总分不变。
验收：关闭模型或模拟超时，运行仍成功且 llmUsed=false。

### 5.5 趋势与归因

**FR-29 趋势聚合**：按月/季/年聚合分析项目数、平均最高分、平均 Top-K 分、高风险项目数、项目对与唯一对数、高风险对数、环比。
验收：趋势点与快照明细复算一致。

**FR-30 趋势筛选**：支持时间范围、项目组、技术方向、基金类型；GROUP_USER 强制本组。
验收：筛选后各指标联动。

**FR-31 趋势下钻**：趋势点 → 项目清单（按等级过滤）→ 项目对明细 → 重复/差异文本。
规则：下钻条件写入 URL。
验收：刷新页面后下钻条件保持。

**FR-32 归因与热力图**：四类归因计数与占比、项目组归因矩阵、项目组×月份与技术方向×项目组热力图。
验收：四类归因计数之和等于项目对数（按视角口径）。

### 5.6 投入态势

**FR-33 投入 KPI**：总投入、项目数、在研/结项数、平均预算、已分析数、平均最高分、高风险项目数、风险敞口。
规则：口径为已批准、进行中、已结项项目。
验收：KPI 与项目明细复算一致。

**FR-34 多维分布**：按年度、基金类型、项目组、技术方向分布，Top 高风险项目。
验收：各维度合计与总量一致。

**FR-35 投入导出**：CSV/Excel 导出，含口径说明与生成时间。
验收：导出文件可打开且数字与页面一致。

### 5.7 辅助决策与报告

**FR-36 决策预检**：支持项目模式与文本模式，输出风险分、等级、Top-K 相似项目、重复/差异点、建议动作、预计重复投入、建议专家。
验收：预检结果与项目重复度报告一致。

**FR-37 决策规则**：按优先级升序匹配首个启用规则，支持分数区间、关系、同组条件与动作；未命中回退 EXPLAIN。
规则：规则必须覆盖 0–100 完整区间；仅 ADMIN 可改。
验收：调整规则后同一预检得到新建议动作。

**FR-38 决策记录**：保存预检快照、建议、操作人、时间；支持查询、详情与管理员作废。
验收：记录内容与当时预检一致。

**FR-39 报告导出**：Word 决策报告（项目信息、结论、相似项目、重复/差异点、模型复核）与 Excel 相似项目明细。
验收：导出文件可打开，内容与页面一致，含口径说明。

**FR-40 报告与数据权限**：导出受数据范围约束，导出动作写审计。
验收：GROUP_USER 无法导出他组项目记录。

### 5.8 系统管理与审计

**FR-41 用户管理**：新增、编辑、启停、重置密码、分配角色与项目组。
规则：禁用后旧 token 立即失效。
验收：禁用用户立即无法访问。

**FR-42 组织与字典**：项目组、技术方向树形维护。
规则：被引用时不可删除。
验收：删除被引用字典返回 400。

**FR-43 角色与权限查看**：展示固定角色及权限点。
验收：页面与 PermissionCatalog 一致。

**FR-44 系统参数**：维护 `review.requiredPassCount`（1–10）。
验收：修改后立项门禁生效。

**FR-45 审计日志**：按时间、操作人、动作、资源筛选，支持 CSV 导出，不可界面删除。
验收：写操作均可在审计日志查到，敏感字段显示为 `***`。

### 5.9 待办与交付

**FR-46 待办中心**：按角色汇总草稿、被驳回、待审查、待立项、未评审项目。
验收：四类角色待办与项目状态一致。

**FR-47 演示数据**：60 个项目、8 个项目组、2024–2026 提交时间，覆盖四类归因与低重复场景；幂等可重启。
验收：首次启动生成 60 项目，重复启动不重复插入。

**FR-48 部署与备份**：H2 演示模式零依赖启动；MySQL 8 建表脚本；数据库备份/恢复脚本；Docker 配置。
验收：全新环境按文档可启动并完成演示。

## 7 数据需求与约束

### 7.1 核心数据实体

| 实体 | 说明 | 主要关系 |
|------|------|----------|
| 用户/角色/项目组 | 账号与组织基础 | 用户属于项目组，拥有多角色 |
| 项目 | 立项主数据与状态 | 属于项目组与技术方向，含结构化内容 |
| 申报内容 | 目标、研制内容、关键技术、节点、成员 | 一对多挂靠项目 |
| 附件 | 原始申报书与解析文本 | 属于项目 |
| 评审与审批轨迹 | 专家评审记录、状态流转记录 | 属于项目 |
| 分析运行/项目对/快照 | 重复度结果与时间序列 | 运行产生项目对与快照 |
| 分析配置 | 权重、阈值与模型参数 | 版本化，单条生效 |
| 决策规则/记录 | 建议动作与预检留痕 | 记录引用运行与项目 |
| 系统参数/审计日志 | 运行参数与操作留痕 | 全局 |

### 7.2 数据规模与留存

- 演示数据：60 个项目、8 个项目组、12 个技术方向、14 个月趋势点。
- 单项目分析项目对上限：Top-K 并集（默认 K=5）。
- 分析快照按运行留存，历史回填只写快照。
- 附件存储于 `UPLOAD_DIR`，默认 `./storage`；数据库仅存元数据与解析文本。

### 7.3 备份与恢复

- 演示库为 H2 文件库 `./data/funddb.*`，提供备份与恢复脚本。
- 生产为 MySQL 8，提供全量建表与初始化脚本。
- 备份文件需校验可解压、可启动；恢复后核心数据量与备份时一致。

### 7.4 约束与假设

- 仅解析有文本层的 docx/pdf/txt/md，不做扫描件 OCR。
- 大模型通过 OpenAI 兼容接口调用，默认关闭。
- 审批状态机固定，不支持自定义流程设计器。
- 部署环境具备 JDK 8、Node 18+；评审演示使用 H2。

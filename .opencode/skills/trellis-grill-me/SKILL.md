# Trellis Grill-Me（需求澄清）

在 `trellis-brainstorm` 之前使用本 skill。目标：把含糊的原始诉求拷问成一组明确、无歧义、用户已确认的需求决策，再进入 brainstorm 的规划产物编写。

参考 mattpocock grilling 模式：把需求映射为**设计树**——每个决策分支出它挂着的下游决策，按**轮**工作。**frontier** = 前置决策已定的所有问题：现在就能问、不必靠猜测答案的问题。每轮把整个 frontier 编号问出（Q1..Qn，**每轮 ≤5 个**，超出顺延下轮），每题附推荐答案与权衡，等用户回答后再进入下一轮。

## 非协商原则

1. **每轮问整个 frontier，一次编号多问**。计算 frontier 后按依赖顺序编号列出 Q1、Q2、…（每轮最多 5 个），每题附推荐答案与权衡，一轮问出等待回复。依赖本轮其他未答问题的问题属于后续轮，不在本轮问。不要一次只问一个问题——那会把澄清拖成长串低信息密度对话，业务问题整体问得太少。
2. **事实查环境，决策问用户**。凡是能通过探索代码库、测试、配置、文档、既有任务或会话历史回答的问题，必须先查证再回答，绝不拿来问用户。只有产品意图、偏好、范围边界、风险容忍度、验收行为这些无法从仓库推断的决策，才交给用户。需要环境事实时可分发 sub-agent 并行查证，不阻塞当轮提问：取证中的问题视为未决前置，只挂起依赖它的下游问题，其余 frontier 照常问出。
3. **每个问题必须附推荐答案与权衡**。格式：需要的决策 + 为什么重要 + 我的推荐 + 若选其他方案的代价。推荐不等于替你决定——收到回复前不得把推荐当成既定决策。
4. **逐轮重算 frontier**。每轮用户的回答重塑设计树：已定决策把 frontier 向外推，解锁依赖它们的问题；重算 frontier 后进入下一轮。决策依赖链大致为：范围 → 用户/目标 → 验收标准 → 技术取舍。
5. **达成共识前不动手**。在用户明确确认共享理解之前，不得编写产品代码、不得分发实现 agent、不得运行 `task.py start`。
6. **结论必须落盘**。每轮澄清后立即把确认的结论写入 `prd.md`（或任务目录下的澄清记录文件），绝不只留在对话里——对话会被压缩，文件不会。

## 流程

### 第 1 步：复述并拆解

把用户原始诉求复述为一句问题陈述，识别其中的：

- 已确认事实（可查证/已明确）
- 需要用户决策的空白点（范围、目标用户、验收标准、优先级、风险偏好）
- 可能的歧义（同一句话的多种解读）

### 第 2 步：先取证、建设计树

用代码、文档、既有任务证据填掉能填的空白。每个准备问的问题先自问：

- 仓库里有没有答案？→ 有就查，不问
- 这是产品意图还是技术事实？→ 技术事实自己查（必要时分发 sub-agent 并行查），产品意图才问
- 这个问题在决策树上是否已被更上游的问题覆盖？→ 是就跳过

然后把剩余的用户决策空白组织成设计树：每个决策下挂它解锁的下游决策。

### 第 3 步：逐轮拷问（frontier 多问）

每轮：

1. 计算 frontier：前置决策已定的所有问题。
2. 按依赖顺序编号列出（每轮 ≤5 个；超出的留待下轮），每题格式：

```
❓ Q1 - <问题标题>：<问题正文，说明需要的决策、为何影响后续规划、可选方案>

➡️ <推荐答案>

<若选其他方案的权衡>
```

3. 等用户逐题回答后，把已确认决策落盘，重算 frontier，进入下一轮。

不要问过程类问题（"要我搜索吗""继续澄清吗"）。证据工作直接做，只把产品决策留给用户。

### 第 4 步：收敛确认

当 frontier 为空——设计树的每个分支都已访问、没有静默假设——向用户呈现澄清摘要（已确认决策 + 每条的来源/依据），请用户确认"共享理解达成"。确认后本 skill 结束，把已落盘的结论交给 `trellis-brainstorm` 继续规划产物编写。

## 与 trellis-brainstorm 的边界

- 本 skill：只做需求澄清，不产出设计/实施文档。
- brainstorm：承接澄清结论，创建任务目录、编写 `prd.md`（含验收标准）、复杂任务补充 `design.md` / `implement.md`、主持最终评审。
- 若澄清过程中发现需求超出一个任务的合理范围，记录建议拆分的线索（候选子任务清单），由 brainstorm 决定是否拆父子任务。

## 澄清记录格式（写入 prd.md 的约定）

每个已确认决策记录为：

```markdown
- [x] <决策>：<结论>（依据：<用户原话 / 仓库证据>）
```

未决决策记录为：

```markdown
- [ ] <决策>：待定 —— <为什么还没定 / 卡在哪个上游决策>
```

## 质量门槛

- 澄清摘要中的每一项决策都有用户确认或仓库证据支撑，无"我猜的"。
- frontier 为空：设计树全部分支已访问，无静默假设；未决阻塞问题为空（或已显式降级为 brainstorm 阶段的 defer 项）。
- 全部结论已写入 `prd.md`，对话中无孤儿结论。

# 交付物与部署验证（PRD）

## Goal

把可运行的系统、可复现的数据、可恢复的备份、与系统一致的文档和演示材料交付到比赛门户与代码仓库，确保评审在无开发环境的情况下也能理解并验证产品价值。

## 范围

- 演示数据：3 个年度、8 个项目组、约 60 个项目，覆盖四类归因与高/中/低重复。
- 历史趋势回填：生成 12–14 个月的分析快照，使趋势与归因看板开箱可演示。
- 开源样例附件：获取 4–6 份公开开源文档，生成/整理为可解析的 docx/pdf/md 样例。
- 数据库：MySQL 8 初始化脚本、H2 演示库、备份脚本与可恢复备份文件。
- 文档：README、需求分析、系统设计、数据库设计、接口、用户手册、指标口径、演示脚本、提交清单。
- 截图与演示：关键页面运行截图（Playwright）、演示视频脚本/分镜。
- 部署：H2 单机启动、Docker Compose、WeCode 部署说明与验证记录。
- 最终质量：构建、测试、权限矩阵、端到端回归、无密钥检查。

## D0 演示数据基线（提前执行，2026-10-31）

为了 B1/B2 一开工就有可演示数据，先执行原 F1/F2 的数据部分：

- 清理本地 `data/`，用 `DemoDataInitializer` 重建 60 个项目（旧 8 个 `DEMO-TREND-*` 历史项目作废）。
- 固定构造规则、`DEMO-` 前缀幂等、`DEMO_DATA_SEED=false` 可关闭、`test` profile 跳过。
- 覆盖 2024–2026 三个年度、8 个项目组、7 种状态；10 对近似主题（同组 2 对、跨组间隔 3 个月 6 对、跨组 10 天内 2 对），其余 40 个低重复。
- 用 `scripts/backfill-trend.ps1 -Months 14` 生成近 14 个月月末快照。
- 验收：项目 60 个；趋势 ≥12 个点；`self/our/peer/simultaneous` 四类均 >0；任选月份可复算；草稿不进入分析语料。
## 功能需求

### F1 演示数据

- 8 个项目组、4 类角色、至少 8 个演示用户；密码统一演示强度并在 README 说明。
- 60 个项目分布在 2024–2026，状态覆盖草稿、已提交、评审中、已立项、在研、结项、驳回。
- 基金类型、技术方向、预算、起止时间分布合理；预算 30 万–300 万。
- 内容模式（可复现，固定随机种子）：
  - 同组高度重复 2 组（本组内部）
  - 跨组、对方在先 3 组（他组在先）
  - 跨组、我方在先 3 组（我方在先）
  - 跨组、30 天内 2 组（同期并行）
  - 低重复/无关 其余
- 每个项目有完整目标、研制内容、关键技术、节点计划、成员；至少 20 个项目有关联附件。
- 演示数据初始化幂等：重复启动不重复插入；可通过配置关闭。

### F2 历史趋势回填

- 以最近 14 个月的月末为 `analysisDate`，按当时已提交项目生成分析运行与快照。
- 回填仅演示 profile 或 ADMIN 显式触发；结束时间不晚于当前日期。
- 回填后趋势页至少 12 个数据点，四类归因均有样本；最新月份结果与当前分析一致。
- 回填过程可中断重跑；同一日期重复回填先清理旧 run（或跳过）。

### F3 开源样例附件

- 从公开开源仓库获取 4–6 份文档（优先中文 README/设计文档），保存来源 URL、许可证与获取日期到 `docs/demo-data.md`。
- 至少 2 份 docx（由开源文档内容构造的四段式申报书样例）、2 份 pdf/md，用于演示解析。
- 网络不可用时使用内置生成的样例文本，并在文档标注“离线生成”。
- 不引入受版权限制或含敏感信息的材料。

### F4 数据库与备份

- `db/mysql/schema.sql` + `db/mysql/data.sql`（或 mysqldump 文件）可在 MySQL 8 空库恢复。
- H2 演示库位于 `data/`，提供 `scripts/backup-h2.ps1`（停止服务后压缩）与恢复说明。
- 实际生成一份可恢复备份文件放入 `db/backup/`，并在空目录验证恢复。
- 备份文件不含真实敏感数据；README 写明备份时间与版本。

### F5 文档

- `README.md`：项目简介、功能清单、技术栈、环境要求、H2/MySQL/Docker 启动步骤、演示账号、目录结构、常见问题、部署地址占位。
- `docs/requirements-analysis.md`：功能/非功能需求、角色、业务流程、用例。
- `docs/design.md`：架构、模块、数据流、关键算法、部署。
- `docs/A阶段产品设计书.md`：A 阶段产品与交互基线（已在规划阶段产出，交付时随实现更新）。
- `docs/database.md`：ER 说明、表结构、索引、口径。
- `docs/api.md`：接口清单、鉴权、错误码、示例。
- `docs/user-guide.md`：按角色的操作步骤，含截图。
- `docs/metrics.md`：重复度、等级、归因、风险敞口、同比的精确口径与示例计算。
- `docs/demo-data.md`：数据分布、开源样例来源与许可、账号。
- `docs/demo-script.md`：5 分钟演示脚本（分镜、台词、预期画面）。
- `docs/submission-checklist.md`：四项交付物与门户填报信息。

### F6 截图与演示

- 使用 Playwright 登录后截取：登录、总览、项目列表、项目详情、申报书解析、分析报告、趋势归因、投入态势、辅助决策、决策记录、系统管理（≥10 张）。
- 截图 1440×900，中文清晰，无敏感信息；存入 `docs/screenshots/`。
- 演示脚本包含：问题背景 → 申报与解析 → 重复度分析 → 趋势归因（重点）→ 投入态势 → 辅助决策 → 交付说明。
- 若无法录制视频，交付脚本 + 截图 + 可访问地址，并在文档说明。

### F7 部署

- H2 单机：`java -jar` 一条命令，自动建库与演示数据；验证冷启动、重启数据保留。
- Docker：`Dockerfile` + `docker-compose.yml`（MySQL 8 + 应用），健康检查、数据卷、环境变量。
- WeCode：部署步骤、端口、环境变量、静态资源配置；记录实际部署地址与验证时间。
- 生产配置无默认弱密钥；首次启动强制修改管理员密码的提示（或 README 强提示）。

### F8 最终质量

- 全量 `mvn clean test`、`mvn package`、`npm run build` 通过。
- 权限矩阵（4 角色 × 关键接口/页面）逐项验证。
- 端到端回归：创建 → 解析 → 提交 → 评审 → 立项 → 分析 → 趋势 → 投入 → 预检 → 报告。
- 仓库检查：无密钥、无真实敏感数据、无大文件；`.gitignore` 完整。
- 交付清单逐项打勾。

## 验收标准

- [ ] 至少 2 份 docx 与 2 份其他格式样例可上传并解析成功；来源与许可记录完整。
- [ ] 备份文件可在空环境恢复并登录；恢复步骤经实测。
- [ ] 文档齐全且与系统一致；截图覆盖 ≥10 个关键页面；演示脚本可照读执行。
- [ ] Docker Compose 文件语法有效；WeCode 部署地址可访问（若环境可用），否则明确记录阻塞原因。
- [ ] 权限矩阵与端到端回归全部通过；控制台无报错。
- [ ] 仓库无密钥/敏感信息；`git status` 干净（除交付物）。
- [ ] 提交清单四项（应用地址、代码仓库、数据库备份、文档）均有对应产物。

## 依赖与约束

- 前置：所有功能子任务完成。
- 本机无 Docker/MySQL：Docker 与 MySQL 恢复需在 WeCode/目标环境验证；本地以 H2 为准并如实记录。
- 开源样例需遵守许可证，仅用于演示解析，不作为真实申报材料。
- 截图与视频不得出现本机路径、Token、密钥。

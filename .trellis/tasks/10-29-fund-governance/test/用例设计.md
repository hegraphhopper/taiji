# C1 角色权限、系统管理与审批流 — 用例设计

## 用例设计摘要

- 被测范围：系统参数、用户管理、项目组/技术方向管理、权限矩阵与数据范围、专家评审、审批流状态机、审计查询与导出。
- 口径：PASS 数按「项目全部轮次中 result=PASS 的不同专家」去重统计，同一专家多轮 PASS 只计 1 人；默认 2，可在 1–10 内配置。
- 动作权限：项目组负责提交/撤回/开始执行/结项；PMO 负责形式审查/立项/驳回/终止；ADMIN 可执行全部业务动作；EXPERT 只提交评审，不改状态。
- 数据范围：ADMIN/PMO 全所；GROUP_USER 仅本组；EXPERT 见全部 `REVIEWING` + 本组非草稿项目。
- 测试栈：JUnit 5 + Spring Boot Test + MockMvc，`@ActiveProfiles({"demo","test"})` + H2 内存库。

## 单元用例

### UT-G01 系统参数默认值与更新
- 关联需求：F4、澄清 C1-PASS 配置
- 被测对象：`SystemConfigController` / `SystemConfigService`
- 前置条件：V6 种子 `review.requiredPassCount=2`
- 输入：读取列表与单项；更新为 3、再更新为 1
- 预期结果：默认 2；更新即时生效；`SYSTEM_CONFIG_UPDATE` 审计存在
- 优先级：P0

### UT-G02 系统参数权限与校验
- 关联需求：F1、F2
- 被测对象：`GET/PUT /api/v1/system/configs/{key}`
- 前置条件：PMO 登录
- 输入：PMO 读写；ADMIN 提交 `0`、`11`、`abc`
- 预期结果：PMO 403；非法值 400 且值保持合法范围
- 优先级：P0

### UT-G03 用户新增、重置密码与禁用生效
- 关联需求：F2、验收第 3 条
- 被测对象：`UserAdminService`
- 前置条件：ADMIN 登录
- 输入：新增用户；重置密码；禁用后用旧 token 访问
- 预期结果：新增可登录；重置返回一次性临时密码；禁用后旧 token 立即 401
- 优先级：P0

### UT-G04 用户管理权限与删除保护
- 关联需求：F1、F2
- 被测对象：`/api/v1/users`
- 前置条件：PMO、GROUP_USER 登录
- 输入：非管理员访问；删除仍有引用的组织/字典
- 预期结果：非管理员 403；有用户或项目的组、被项目引用的技术方向删除返回 400
- 优先级：P0

### UT-G05 用户检索与角色分配
- 关联需求：F2
- 被测对象：`UserAdminService.list/updateRoles`
- 前置条件：存在多角色用户
- 输入：按用户名/角色/状态筛选；调整角色
- 预期结果：分页与筛选正确；角色变更后权限点随之变化；响应不含密码哈希
- 优先级：P1

### UT-G06 PASS=2 门禁与完整审批链
- 关联需求：F4、验收第 5、6 条
- 被测对象：`ProjectWorkflowService.approve` / `/projects/{id}/reviews`
- 前置条件：项目 `REVIEWING`，配置 PASS=2
- 输入：1 位专家 PASS 后立项；第 2 位专家 PASS 后再立项；随后开始执行、结项
- 预期结果：1 票时 400 且仍 `REVIEWING`；2 票后 `APPROVED`；`reviewPassCount=2`；`START`、`COMPLETE` 成功
- 优先级：P0

### UT-G07 驳回重提、轮次与 PASS 去重
- 关联需求：F4、澄清「同一专家多轮 PASS 只计 1 人」
- 被测对象：`ProjectReviewService.passCount`
- 前置条件：第 1 轮专家 A PASS 后驳回并重新提交
- 输入：第 2 轮读取 `reviewPassCount`；直接立项；专家 A、B 再评审后立项
- 预期结果：第 2 轮 `reviewPassCount=1`（A 旧 PASS 仍计入）；1 票时立项 400；A 重复 PASS 仍只计 1 人；B PASS 后达 2 票立项成功
- 优先级：P0

### UT-G08 非法流转、越权动作与终止
- 关联需求：F4、验收第 6 条
- 被测对象：`/projects/{id}/actions`
- 前置条件：项目组用户、PMO
- 输入：草稿直接 START；项目组用户 ACCEPT；立项后 PMO TERMINATE
- 预期结果：非法流转 400；越权 403；终止需意见并进入 `TERMINATED`
- 优先级：P0

### UT-G09 评审唯一性与待办
- 关联需求：F4、F5
- 被测对象：`ProjectReviewService.submit` / `TodoService`
- 前置条件：`REVIEWING` 项目
- 输入：专家本轮提交两次；查看待办
- 预期结果：重复提交 400；评审后本人待办移除；PMO 待办可见待立项/待审查项
- 优先级：P1

### UT-G10 新一轮评审与草稿范围
- 关联需求：F4、F1
- 被测对象：评审接口 + 项目可见范围
- 前置条件：驳回后重新进入 `REVIEWING`
- 输入：第 2 轮重新评审；专家访问草稿
- 预期结果：新一轮可再次评审；草稿对专家不可见；历史评审记录保留且不可修改
- 优先级：P1

### UT-G11 审计查询、导出与脱敏
- 关联需求：F3、验收第 4 条
- 被测对象：`AuditLogController`
- 前置条件：已产生登录、用户变更等审计
- 输入：条件查询；导出 CSV；检查详情
- 预期结果：倒序分页；CSV 带 BOM 且可解析；密码/Token 显示为 `***`
- 优先级：P0

### UT-G12 审计筛选与结果过滤
- 关联需求：F3
- 被测对象：`AuditLogService.wrapper`
- 前置条件：成功与失败审计并存
- 输入：按资源类型、结果筛选
- 预期结果：仅返回匹配记录；非 ADMIN 403
- 优先级：P1

### UT-G13 四角色关键接口权限矩阵
- 关联需求：F1、验收第 1 条
- 被测对象：管理、分析、趋势、投入、决策、项目接口
- 前置条件：admin/pmo01/user01/expert01
- 输入：逐接口允许/拒绝矩阵
- 预期结果：ADMIN 全通过；PMO 无系统管理、可分析/看板/决策；GROUP_USER 仅本组业务；EXPERT 仅项目/评审/待办/决策记录，趋势投入分析 403
- 优先级：P0

### UT-G14 数据范围、专家可见性与项目动作边界
- 关联需求：F1、F4、验收第 2、8 条
- 被测对象：`ProjectAccessService` / `ProjectQueryService` / 项目动作
- 前置条件：两个项目组、专家、PMO
- 输入：组用户访问他组项目；专家访问他组 `REVIEWING` 与草稿；PMO 创建/提交/开始项目
- 预期结果：组用户 403；专家可见 `REVIEWING`、不可见草稿；PMO 项目维护类动作 403（仅审查/立项/驳回/终止）
- 优先级：P0

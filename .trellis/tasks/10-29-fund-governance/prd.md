# 角色权限、系统管理与审批流（收尾）（PRD）

## Goal

在核心主线（申报书、重复度、趋势归因）与增强功能（投入、决策）稳定后，补齐四类角色的细粒度权限、系统管理界面、审计查询与完整审批流，使系统符合所内基金项目管理规范并可正式运营。

## 前置

- foundation 已完成最小登录、JWT、角色枚举、SecurityContext、数据范围钩子、审计写入。
- declaration 已完成项目与申报书结构化、附件解析、基础状态闭环。
- 其余子任务已验收，数据口径稳定。

## 范围

- 细粒度权限矩阵：4 角色 × 页面 × 接口；数据范围在项目、分析、趋势、投入、决策全链路生效。
- 系统管理：用户、项目组、技术方向、角色查看/分配、启用/禁用、重置密码。
- 审计日志查询与导出。
- 审批流：形式审查、专家评审（多轮、评分、意见、结论）、立项/驳回、在研/结项/终止。
- 审批轨迹与评审记录页面、待办列表。
- 不做：可视化流程设计器、多级会签自定义、统一身份对接。

## 功能需求

### F1 权限矩阵

- `ADMIN`：全部系统管理、配置、审计；可执行所有业务动作。
- `PMO`：全部项目查看、形式审查、立项/驳回/终止、分析运行、看板、决策、报告导出；不可管理用户与系统配置（分析权重除外，按父 PRD 由 ADMIN/PMO 协商，默认 ADMIN）。
- `GROUP_USER`：本组项目创建/编辑/提交/撤回/预检/查看本组分析；不可审查、不可看全所看板。
- `EXPERT`：被指派或已提交项目的只读内容 + 重复度报告 + 评审提交；不可编辑项目、不可看全所趋势/投入。
- 接口与页面双重校验；数据范围在服务层强制，不能只靠前端。
- 越权返回 403 并写审计；禁止通过 ID 猜测访问他组资源。

### F2 系统管理

- 用户：分页检索（用户名/姓名/组/状态/角色）、新增、编辑、启用/禁用、重置密码、分配角色；禁用立即失效（token 校验用户状态）。
- 项目组：树形列表、新增、编辑、启停、删除（有用户或项目时拒绝）；支持调整上级。
- 技术方向：树形列表、新增、编辑、启停、关键词维护、排序；被项目引用时禁止删除。
- 角色：列表与权限点查看；角色代码固定，不可新增删除（避免权限漂移）。
- 所有变更写审计，敏感字段脱敏。

### F3 审计日志

- 查询：时间范围、操作人、动作、资源类型、结果；倒序分页；详情展示请求摘要与 IP。
- 导出 CSV（当前筛选）。
- 不可删除/修改；仅 ADMIN 可见。
- 覆盖：登录/登出/锁定、用户与角色变更、组织与字典变更、项目状态流转、附件上传/删除、分析运行、配置变更、决策保存/导出、报告导出。

### F4 审批流

- 完整状态机：`DRAFT → SUBMITTED → REVIEWING → APPROVED / REJECTED`；`REJECTED → SUBMITTED`；`APPROVED → IN_PROGRESS → COMPLETED / TERMINATED`。
- 动作权限：
  - 项目组：提交、撤回、重新提交、开始执行、结项。
  - PMO：形式审查通过、驳回、立项、终止。
  - 专家：提交评审记录（评分 0–100、意见、结论 PASS/REJECT/REVISE），不直接改状态。
- 立项前置：至少 1 条专家 `PASS`（可配置为需要 N 条）；驳回必须填意见。
- 每次流转写审批轨迹与审计；并发使用乐观锁。
- 待办：项目组看待提交/被驳回；PMO 看待审查/待立项；专家看待评审任务。
- 评审记录支持多轮，历史不可修改；补充评审单独成轮。

### F5 页面

- 系统管理：用户、项目组、技术方向、角色、审计日志、分析权重配置入口。
- 项目：评审任务列表、评审弹窗、待办中心、审批轨迹时间线。
- 角色差异：菜单、按钮、数据范围同时生效；专家隐藏趋势/投入菜单。
- 空态、加载态、错误态、二次确认完整。

- [x] 数据范围全链路生效：GROUP_USER 在项目、分析报告、趋势、投入、决策、导出中均只能获取本组数据。

## 依赖与约束

- 依赖全部前置子任务；本任务不改变分析口径与数据结构（除必要索引）。
- 固定角色代码，不引入自定义角色，避免权限模型复杂化。
- 与统一身份对接不在本期范围，预留 `UserDetailsService` 扩展点。

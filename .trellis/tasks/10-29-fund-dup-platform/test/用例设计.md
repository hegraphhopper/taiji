# 大模型收口 — 单元用例设计

## 1. 摘要

- 被测范围：分析配置默认权重、`LlmClient` 有界重试、`ScoreFusion` 融合、熔断计数口径。
- 测试优先级：P0 覆盖“解释层默认 100/0”和“重试不改变降级语义”；P1 覆盖重试边界与日志口径。
- 执行方式：JUnit 5（`src/test/java`），沿用现有 `LlmFallbackTest`、`ScoreFusionTest`、`AnalysisConfigServiceTest` 结构；前端以 `npm run typecheck` + `npm run build` 验证默认值类型与构建。

## 2. 单元用例

### UT-30 分析配置未显式传权重时默认解释层 100/0
- 关联需求/AC：AC-13
- 被测对象：`AnalysisConfigService#save(AnalysisConfigRequest)`
- 前置条件：Mock `AnalysisConfigMapper`；请求中 `localWeight`、`llmWeight` 为 null。
- 输入：合法字段权重、阈值、Top-K、同期窗口，未提供 LLM 权重。
- 步骤：1. 调用 `save`；2. 读取返回 VO。
- 预期结果：`localWeight=100`、`llmWeight=0`。
- 优先级：P0

### UT-31 大模型权重为 0 时总分保持本地分
- 关联需求/AC：AC-13
- 被测对象：`ScoreFusion#fuse(double, Double, int, int)`
- 前置条件：无。
- 输入：`local=91.60`、`llm=90.0`、`localWeight=100`、`llmWeight=0`。
- 步骤：1. 调用融合；2. 比较结果。
- 预期结果：返回值等于 `91.60`（误差 ≤0.01），不因模型分变化。
- 优先级：P0

### UT-32 超时后重试一次成功
- 关联需求/AC：AC-14
- 被测对象：`LlmClient#call(...)`
- 前置条件：`StubTransport` 第一次返回 `statusCode=0, timeout=true`，第二次返回合法 JSON；使用新 `LlmCircuitBreaker`。
- 输入：启用状态、合法 `LlmOptions`、请求 hash 唯一。
- 步骤：1. 调用一次；2. 检查状态、调用次数、日志条数与熔断计数。
- 预期结果：`status=SUCCESS`、`semanticScore` 与响应一致；`transport.calls=2`；`logs.size()=1` 且状态为 `SUCCESS`；`breaker.failures()=0`。
- 优先级：P0

### UT-33 连续 5xx 重试后仍失败，只记一条失败日志
- 关联需求/AC：AC-14
- 被测对象：`LlmClient#call(...)`
- 前置条件：`StubTransport` 连续两次返回 `statusCode=500`。
- 输入：同上。
- 步骤：1. 调用一次；2. 检查状态与日志。
- 预期结果：`status=HTTP_ERROR`；`transport.calls=2`；`logs.size()=1`；日志 error 为 `HTTP 500`；`breaker.failures()=1`。
- 优先级：P1

### UT-34 4xx 不重试
- 关联需求/AC：AC-14
- 被测对象：`LlmClient#call(...)`
- 前置条件：`StubTransport` 返回 `statusCode=400`。
- 输入：同上。
- 步骤：1. 调用一次；2. 检查调用次数。
- 预期结果：`status=HTTP_ERROR`；`transport.calls=1`；`logs.size()=1`。
- 优先级：P1

### UT-35 熔断按“调用”计数，重试不额外累加
- 关联需求/AC：AC-14
- 被测对象：`LlmClient#call(...)` + `LlmCircuitBreaker`
- 前置条件：每次调用均两次超时；共享同一个 breaker。
- 输入：连续 4 次调用。
- 步骤：1. 前 3 次调用失败；2. 第 4 次调用。
- 预期结果：前 3 次状态均为 `TIMEOUT`，`transport.calls=6`；第 4 次返回 `DISABLED` 且不再发起传输；`logs=3`；`breaker.isOpen()=true`。
- 优先级：P0

### UT-36 缓存命中不发起传输
- 关联需求/AC：AC-14
- 被测对象：`LlmClient#call(...)`
- 前置条件：同一 key 首次成功返回。
- 输入：相同请求连续调用两次。
- 步骤：1. 第一次调用；2. 第二次调用。
- 预期结果：第二次 `isCached()=true`，`transport.calls=1`，`logs.size()=1`。
- 优先级：P1

# A3 重复度分析引擎 — 用例设计

## 用例设计摘要

- 被测范围：分析配置（校验/版本/权限）、文本归一化与分词、TF-IDF 与相似度、五维打分与权重融合、归因判定、片段提取、大模型增强与降级、分析运行编排与并发保护、快照聚合与项目分回写、查询接口与数据范围、性能门禁。
- 测试环境：Spring Boot Test + H2 内存库 + MockMvc；`@ActiveProfiles({"demo","test"})`；大模型通过本地 mock HTTP 服务或 `RestTemplate` 桩替代，不依赖外网与真实密钥。
- 夹具口径：完全相同文本、主题无关文本、部分重叠文本（同技术方向不同场景）；跨组项目通过不同 `group_id` 与可控 `submit_time` 构造。
- 优先级：P0 覆盖打分/归因/权重/降级/快照一致性/权限；P1 覆盖配置版本、并发、缓存、预检不写回、analysisDate；P2 覆盖边界值与性能计时。
- 不在范围：趋势图表、投入看板、决策建议与报告导出（A4/B）以及前端页面交互（由前端构建与浏览器验收覆盖）。

## 单元用例

### UT-01 默认配置随迁移初始化
- 关联需求/AC：F1；AC-1（配置可读）
- 被测对象：Flyway `V4__analysis_schema.sql` + `AnalysisConfigService.current()`
- 前置条件：空库冷启动
- 输入：无
- 步骤：1. 启动上下文 2. 读取当前配置
- 预期结果：存在 version=1、active=1 的配置；权重为 goal15/content35/tech35/milestone5/tag10；阈值 80/60/40；topK=5；同期 30 天；本地/大模型 70/30；llm_enabled=0
- 优先级：P0

### UT-02 配置保存生成新版本并失效旧版本
- 关联需求/AC：F1；AC-1
- 被测对象：`AnalysisConfigService.save(request)`
- 前置条件：已存在 version=1（active=1）；ADMIN 登录
- 输入：合法新权重与阈值
- 步骤：1. 保存 2. 查询当前配置 3. 查询历史
- 预期结果：返回 version=2；当前配置为 v2；历史含 v1、v2；数据库中仅 v2 `active=1`；审计新增一条 CONFIG 记录
- 优先级：P0

### UT-03 配置校验拒绝非法值
- 关联需求/AC：F1
- 被测对象：`AnalysisConfigService.save` + 请求 DTO 校验
- 前置条件：ADMIN 登录
- 输入：分别提交 ① 全部权重为 0 ② `low=60,medium=40` ③ `high=101` ④ `topK=0` ⑤ `simultaneousDays=-1` ⑥ 本地权重 0 且大模型权重 0
- 步骤：逐条保存
- 预期结果：六种输入均 400（`BAD_REQUEST`）；配置版本数不变；无新增审计
- 优先级：P0

### UT-04 非管理员不可修改配置
- 关联需求/AC：F1；权限
- 被测对象：`PUT /api/v1/analysis/config`
- 前置条件：PMO 与 GROUP_USER 登录
- 输入：合法配置
- 步骤：分别调用
- 预期结果：均 403；配置不变；历史接口（ADMIN）对应角色访问也返回 403
- 优先级：P0

### UT-05 文本归一化
- 关联需求/AC：F2
- 被测对象：`TextNormalizer.normalize(String)`
- 前置条件：无
- 输入：含全角字符、HTML 标签、制表/连续空格、控制符、大小写英文、超长文本（>20000）
- 步骤：调用 normalize
- 预期结果：全角转半角；HTML 标签移除；空白统一为单空格；控制符移除；英文小写；长度 ≤20000；null 输入返回空串
- 优先级：P0

### UT-06 中文 2-gram 与英文分词
- 关联需求/AC：F2
- 被测对象：`ChineseTokenizer.tokenize(String)`
- 前置条件：术语词典可加载
- 输入：`"智能计算平台 support vector machine v2"`
- 步骤：分词并统计 token
- 预期结果：中文连续段产生 2-gram；英文/数字得到整词 token（≥2 字符）；停用字不单独成 token；结果无空串与纯标点
- 优先级：P0

### UT-07 术语词典加权
- 关联需求/AC：F2
- 被测对象：`ChineseTokenizer.tokenize` + `TermDictionary`
- 前置条件：词典含“知识图谱”
- 输入：`"知识图谱构建"`
- 步骤：分词
- 预期结果：存在 token `知识图谱`，权重=3；普通 2-gram 权重=1；词典未命中词不产生伪术语
- 优先级：P1

### UT-08 空文本降级
- 关联需求/AC：F2、F3；AC-11
- 被测对象：`ProjectAnalysisInput` + `DimensionScorer`
- 前置条件：项目仅有名称，无目标/内容/技术/节点
- 输入：空维度文本
- 步骤：构建输入并打分
- 预期结果：该维度得分 0；不抛异常；报告标记“文本缺失”；总分按剩余维度权重归一化且不出现 NaN
- 优先级：P0

### UT-09 相同文本相似度为 1
- 关联需求/AC：F3；AC-1（相同夹具 ≥95）
- 被测对象：`TfIdfVectorizer` + `CosineSimilarity`
- 前置条件：两项目五维文本完全一致
- 输入：相同文本对
- 步骤：向量化并计算
- 预期结果：各文本维度余弦=1（±1e-6）；标签 Jaccard=1；总分 ≥95；等级 HIGH
- 优先级：P0

### UT-10 无关文本低分
- 关联需求/AC：F3；AC-2（无关 <30）
- 被测对象：`DimensionScorer` + `ScoreFusion`
- 前置条件：两项目技术方向不同、文本无共同关键词
- 输入：无关文本对
- 步骤：计算总分与等级
- 预期结果：总分 <30；等级 NONE
- 优先级：P0

### UT-11 部分重叠落在区间
- 关联需求/AC：F3；AC-3（40–60）
- 被测对象：`DimensionScorer`
- 前置条件：同技术方向、共享部分研制内容、场景不同
- 输入：部分重叠夹具
- 步骤：计算
- 预期结果：总分落在 40–60（含边界）；等级 LOW 或 MEDIUM（按 80/60/40 阈值判定）；分维度得分与手工复算一致（±0.01）
- 优先级：P0

### UT-12 权重归一化与重跑一致性
- 关联需求/AC：F3；AC-4
- 被测对象：`ScoreFusion`
- 前置条件：已知各维度分与权重
- 输入：权重 15/35/35/5/10；再改为 content=100 其余 0
- 步骤：分别计算
- 预期结果：第一种 `Σ(dim×w)/Σw` 复算一致；第二种总分等于 content 维度分（±0.01）；维度权重之和为 0 时抛业务异常而非除零
- 优先级：P0

### UT-13 节点计划相似度
- 关联需求/AC：F3
- 被测对象：`DimensionScorer.milestoneScore`
- 前置条件：两组节点计划，阶段名部分相同
- 输入：① 阶段名全同且时间区间完全重叠 ② 阶段名全异 ③ 一方无日期
- 步骤：计算
- 预期结果：①=100 ②=0 ③时间项=0 仅按名称项计分；结果与「名称 Jaccard×0.6 + 时间重叠×0.4」手工复算一致
- 优先级：P1

### UT-14 同组归因为 SELF_GROUP
- 关联需求/AC：F3；AC-5
- 被测对象：`AttributionResolver.resolve`
- 前置条件：两项目同 `group_id`
- 输入：任意提交时间
- 步骤：判定
- 预期结果：relation=SELF_GROUP，direction=SELF_GROUP；earlierProjectId 按时间可空
- 优先级：P0

### UT-15 跨组先后与同期边界
- 关联需求/AC：F3；AC-5；AC-6
- 被测对象：`AttributionResolver.resolve`
- 前置条件：两项目不同组
- 输入：时间差 ① 31 天 ② 30 天 ③ 29 天 ④ 完全相等
- 步骤：判定
- 预期结果：① 判 A_EARLIER/B_EARLIER 且 earlierProjectId=较早者 ② ③ SIMULTANEOUS ④ 按 projectId 小者为 earlier，direction 为 A_EARLIER
- 优先级：P0

### UT-16 缺失 submit_time 回退 created_at
- 关联需求/AC：F3
- 被测对象：`AttributionResolver.resolve`
- 前置条件：一方 submit_time 为 null
- 输入：created_at 更早
- 步骤：判定
- 预期结果：以 created_at 比较，earlierProjectId 指向 created_at 更早者；不抛空指针
- 优先级：P1

### UT-17 匹配片段与差异点提取
- 关联需求/AC：F3；AC-11
- 被测对象：`MatchSnippetExtractor`
- 前置条件：给定原文与两侧 token 权重
- 输入：共享高频词、单侧特有词
- 步骤：提取
- 预期结果：matchedPoints 每项 ≤200 字且不含重复片段；diffPoints 命中单侧特有词；维度字段正确；空文本维度不产出条目
- 优先级：P1

### UT-18 大模型关闭时纯本地
- 关联需求/AC：F4；AC-7
- 被测对象：`AnalysisExecutor` + `LlmClient`
- 前置条件：配置 llm_enabled=0
- 输入：一次 FULL 运行
- 步骤：运行并查询结果
- 预期结果：运行成功；run.llmUsed=false；pair 的 llmScore 为 null；totalScore=localScore；无 llm_call_log 记录
- 优先级：P0

### UT-19 大模型超时/500/非法 JSON 降级
- 关联需求/AC：F4；AC-8
- 被测对象：`AnalysisExecutor` + `LlmClient` + `LlmResponseParser`
- 前置条件：llm_enabled=1，桩分别返回超时、HTTP 500、非 JSON、越界分数
- 输入：四次运行
- 步骤：逐次运行
- 预期结果：四次运行均 SUCCESS；失败对保留本地分；连续 3 次失败后停止调用；llmUsed=false；llm_call_log 记录 TIMEOUT/HTTP_ERROR/INVALID 且不含 prompt 正文
- 优先级：P0

### UT-20 大模型合法响应融合
- 关联需求/AC：F4；AC-9
- 被测对象：`ScoreFusion` + `LlmClient`
- 前置条件：桩返回合法 JSON（分数 90、overlaps 2 项）
- 输入：本地权重 70/大模型 30，另一次改为 100/0
- 步骤：运行并复算
- 预期结果：totalScore=(70×local+30×90)/100（±0.01）；100/0 时等于本地分；llmReason 落库；越界或超长数组的响应被丢弃
- 优先级：P0

### UT-21 大模型缓存命中
- 关联需求/AC：F4
- 被测对象：`LlmCache`
- 前置条件：相同 projectId/peerId/textHash/configVersion 已缓存
- 输入：同 key 再取；配置版本变化后再取
- 步骤：读取
- 预期结果：同 key 命中且不重复调用（桩计数不增）；版本变化未命中；超过 TTL 或容量上限按设计淘汰
- 优先级：P1

### UT-22 全量运行落库与快照一致性
- 关联需求/AC：F5、F6；AC-10
- 被测对象：`AnalysisExecutor.runFULL` + `AnalysisQueryService`
- 前置条件：至少 3 个项目（含同组与跨组），配置 topK=5
- 输入：FULL 运行
- 步骤：1. 运行 2. 查询 pair 3. 查询 snapshot
- 预期结果：run=SUCCESS 且 projectCount/pairCount 与实际一致；每项目 1 条快照；快照 maxScore/avgTopScore/highPairCount/四类归因计数与 pair 明细聚合复算一致；project.duplicate_score 与 risk_level 更新为最新快照值
- 优先级：P0

### UT-23 并发保护
- 关联需求/AC：F5
- 被测对象：`AnalysisRunService.createRun`
- 前置条件：一个 FULL 运行正在执行（可通过桩阻塞）
- 输入：并发再触发 FULL 与 PROJECT
- 步骤：并发调用
- 预期结果：第二次返回 409 或复用进行中结果（按实现配置择一，但必须一致且不产生并行写入）；最终仅一个 SUCCESS 运行与一套明细；无重复快照
- 优先级：P1

### UT-24 运行失败清理
- 关联需求/AC：F5；NFR-03
- 被测对象：`AnalysisExecutor`
- 前置条件：模拟落库阶段抛异常
- 输入：FULL 运行
- 步骤：运行后查询
- 预期结果：run 标记 FAILED 且 message 非空；本次 run 的 pair 与 snapshot 均不存在（无半成品）；project 分数未被污染
- 优先级：P1

### UT-25 预检不写回项目分数
- 关联需求/AC：F5
- 被测对象：`POST /api/v1/analysis/precheck`
- 前置条件：草稿项目或临时文本
- 输入：`{triggerType:"PRECHECK", text:"..."}` 或 projectId 指向草稿
- 步骤：预检并查询项目
- 预期结果：返回 Top-K 与分数；run.triggerType=PRECHECK；草稿 project.duplicate_score 保持原值；不生成 PROJECT 快照之外的项目主数据变更
- 优先级：P1

### UT-26 analysisDate 历史回填
- 关联需求/AC：F5；趋势依赖
- 被测对象：`AnalysisExecutor` + `AnalysisRunService`
- 前置条件：存在两个不同提交时间的项目
- 输入：ADMIN 指定 analysisDate=较早日期
- 步骤：运行
- 预期结果：语料只含 `submit_time <= analysisDate` 的项目；snapshot.analysis_date 等于指定日期；当前项目分数不回退（非最新运行）；非 ADMIN 指定 analysisDate 返回 403
- 优先级：P1

### UT-27 查询接口与数据范围
- 关联需求/AC：F6；权限
- 被测对象：`GET /api/v1/analysis/projects/{id}`、`/pairs/{id}`、`/runs`
- 前置条件：GROUP_USER 属于 A 组，报告属于 B 组
- 输入：分别以 GROUP_USER、PMO、ADMIN、EXPERT 访问
- 步骤：调用
- 预期结果：GROUP_USER 跨组 403；PMO/ADMIN 200；EXPERT 仅已提交项目可读；未登录 401；返回结构含 project/snapshot/topPeers 与分维度得分
- 优先级：P0

### UT-28 删除失败运行
- 关联需求/AC：F6
- 被测对象：`DELETE /api/v1/analysis/runs/{id}`
- 前置条件：存在 FAILED 运行与 SUCCESS 运行
- 输入：分别删除
- 步骤：调用
- 预期结果：FAILED 删除成功且级联清空其 pair/snapshot；SUCCESS 拒绝（400）；非 ADMIN 403；删除写审计
- 优先级：P1

### UT-29 性能门禁
- 关联需求/AC：F7；AC-10
- 被测对象：`AnalysisExecutor`（本地算法）
- 前置条件：300 个项目夹具，每项目五维文本约 4.5 万字符
- 输入：FULL 运行（llm 关闭）
- 步骤：计时运行
- 预期结果：耗时 ≤5s；堆内存无 OOM（`-Xmx512m`）；pair 条数受 Top-K 限制（≤ 300×5 量级）
- 优先级：P2

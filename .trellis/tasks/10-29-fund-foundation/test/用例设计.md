# A1 平台底座与最小鉴权 — 用例设计

## 用例设计摘要

- 被测范围：登录与账号状态、JWT 过滤器、角色与权限基础设施、数据范围钩子、字典/组织/技术方向只读接口、审计写入、Flyway 种子。
- 测试优先级：P0 覆盖认证、越权、种子与审计；P1 覆盖改密、健康检查、数据范围；P2 覆盖边界与重复调用。
- 测试环境：Spring Boot Test + H2（`MODE=MySQL`）+ MockMvc；不依赖外部网络与 MySQL。
- 说明：A1 不实现项目/分析/趋势，相关业务权限矩阵在 governance 阶段补充。

## 单元用例

### UT-01 正确账号密码登录成功
- 关联需求/AC：AC-A1；foundation 验收第 3 条
- 被测对象：`AuthService.login(LoginRequest)`
- 前置条件：H2 种子已执行，`admin` 已初始化 BCrypt 密码
- 输入：`username=admin`，`password=Admin@123`
- 步骤：1. 调用登录；2. 读取返回 token；3. 解析 token 的 subject
- 预期结果：返回非空 token、`expiresAt` 在未来、用户角色包含 `ADMIN`；登录成功计数清零
- 优先级：P0

### UT-02 密码错误登录失败
- 关联需求/AC：AC-A1
- 被测对象：`AuthService.login`
- 前置条件：`admin` 存在
- 输入：`username=admin`，`password=wrong`
- 步骤：调用登录
- 预期结果：抛出 `BizException`，错误码 `AUTH_BAD_CREDENTIALS(40101)`；不返回 token；失败计数 +1
- 优先级：P0

### UT-03 连续失败 5 次锁定
- 关联需求/AC：AC-A1；PRD F3
- 被测对象：`AuthService.login`
- 前置条件：`admin` 存在且未锁定
- 输入：连续 5 次错误密码
- 步骤：1. 循环调用 5 次；2. 第 6 次使用正确密码
- 预期结果：前 5 次返回 40101；第 6 次返回 `AUTH_LOCKED(40102)`，`locked_until` 晚于当前时间
- 优先级：P0

### UT-04 禁用用户无法登录
- 关联需求/AC：AC-A1；PRD F3/F4
- 被测对象：`AuthService.login`、`UserDetailsServiceImpl`
- 前置条件：存在 `status=DISABLED` 的用户
- 输入：该用户正确密码
- 步骤：调用登录
- 预期结果：返回认证失败或禁用错误码；不签发 token
- 优先级：P0

### UT-05 合法 JWT 可解析并建立认证
- 关联需求/AC：AC-A1
- 被测对象：`JwtTokenProvider.create/parse`、`JwtAuthenticationFilter`
- 前置条件：用户存在
- 输入：合法 Bearer token
- 步骤：1. 访问 `/api/v1/auth/me`；2. 检查响应
- 预期结果：HTTP 200，`data.username` 与签发用户一致，`roles` 正确
- 优先级：P0

### UT-06 非法或过期 JWT 返回 401
- 关联需求/AC：AC-A1
- 被测对象：`JwtAuthenticationFilter`
- 前置条件：无
- 输入：`Bearer invalid.token.value`；以及过期 token
- 步骤：访问 `/api/v1/auth/me`
- 预期结果：HTTP 401，统一 JSON 错误码 `AUTH_TOKEN_INVALID(40103)`，不泄露堆栈
- 优先级：P0

### UT-07 未认证访问受保护接口返回 401
- 关联需求/AC：AC-A1
- 被测对象：`SecurityConfig`
- 前置条件：无 token
- 输入：`GET /api/v1/dicts`
- 步骤：直接请求
- 预期结果：HTTP 401，响应为统一 JSON；`/api/v1/auth/login` 与 `/api/v1/health` 仍匿名可访问
- 优先级：P0

### UT-08 角色不足访问管理员接口返回 403
- 关联需求/AC：AC-A1
- 被测对象：`SecurityConfig`、`@PreAuthorize`
- 前置条件：`user01` 仅 `GROUP_USER`
- 输入：`user01` token 访问仅 ADMIN 接口（如未来的 `/api/v1/audit-logs` 或受保护管理接口）
- 步骤：请求
- 预期结果：HTTP 403，统一错误码 `FORBIDDEN(40301)`；审计记录拒绝结果
- 优先级：P0

### UT-09 当前用户信息完整
- 关联需求/AC：AC-A1
- 被测对象：`AuthController.me`
- 前置条件：`user01` 登录
- 输入：带 token 的 `GET /api/v1/auth/me`
- 步骤：请求并反序列化
- 预期结果：包含 `id/username/realName/groupId/groupName/roles`；不包含 `passwordHash`、`failCount`、`lockedUntil`
- 优先级：P0

### UT-10 字典聚合接口
- 关联需求/AC：AC-A1；PRD F5
- 被测对象：`DictController.dicts`
- 前置条件：V2 种子完成
- 输入：带 token 的 `GET /api/v1/dicts`
- 步骤：请求
- 预期结果：返回基金类型 3 项、项目状态枚举、角色 4 项、技术方向 12 项；技术方向含 `keywords`
- 优先级：P0

### UT-11 项目组与技术方向只读列表
- 关联需求/AC：AC-A1
- 被测对象：`GroupController.list`、`TechDirectionController.list`
- 前置条件：种子完成
- 输入：带 token 的 GET 请求
- 步骤：请求
- 预期结果：项目组 8 项且按排序返回；技术方向 12 项；无写接口暴露（POST/PUT 返回 405 或 403）
- 优先级：P1

### UT-12 登录与登出写审计且敏感字段脱敏
- 关联需求/AC：AC-A1；PRD F6
- 被测对象：`AuditAspect`、`AuditLogMapper`
- 前置条件：登录成功
- 输入：登录与登出请求
- 步骤：1. 登录；2. 登出；3. 查询 `audit_log`
- 预期结果：存在 `LOGIN` 与 `LOGOUT` 记录；`detail` 不含明文密码/token；包含 IP 与结果；密码字段为 `***`
- 优先级：P0

### UT-13 修改密码旧密码错误
- 关联需求/AC：AC-A1
- 被测对象：`AuthService.changePassword`
- 前置条件：用户已登录
- 输入：`oldPassword=wrong`，`newPassword=NewPass@123`
- 步骤：调用
- 预期结果：抛出 `BizException`，错误码 `AUTH_OLD_PASSWORD_INVALID`；密码哈希不变
- 优先级：P1

### UT-14 新密码强度校验
- 关联需求/AC：AC-A1；PRD F3
- 被测对象：`AuthService.changePassword`、DTO 校验
- 前置条件：用户已登录且旧密码正确
- 输入：`newPassword=123456`、`abcdefgh`
- 步骤：分别调用
- 预期结果：均被拒绝，提示长度/字母数字要求；密码哈希不变
- 优先级：P1

### UT-15 演示账号 INIT 哈希初始化
- 关联需求/AC：AC-A1；PRD F3
- 被测对象：`DemoAccountInitializer`
- 前置条件：V2 种子账号 `password_hash=INIT`，demo profile 启动
- 输入：启动应用
- 步骤：1. 启动；2. 查询账号哈希；3. 用演示密码登录
- 预期结果：哈希以 `$2a$`（或 `$2b$`）开头且不等于 `INIT`；演示密码登录成功；重复启动不重复编码
- 优先级：P0

### UT-16 健康检查
- 关联需求/AC：AC-A1；PRD F1
- 被测对象：`HealthController`
- 前置条件：应用启动、数据库可用
- 输入：`GET /api/v1/health`
- 步骤：请求
- 预期结果：HTTP 200；`status=UP`；包含 `profile=demo`；数据库状态 `UP`
- 优先级：P1

### UT-17 Flyway 种子与幂等
- 关联需求/AC：AC-A1；PRD F2
- 被测对象：Flyway V1/V2
- 前置条件：空 H2 文件库
- 输入：启动两次
- 步骤：1. 首次启动；2. 记录表与种子数量；3. 重启
- 预期结果：角色 4、项目组 8、技术方向 12、用户 4；二次启动不重复插入，Flyway 版本一致
- 优先级：P0

### UT-18 数据范围钩子
- 关联需求/AC：AC-A1；PRD F4
- 被测对象：`DataScopeService`
- 前置条件：`user01` 属项目组 1，存在项目组 2（A1 阶段仅用内存/桩验证钩子）
- 输入：`GROUP_USER` 当前用户
- 步骤：调用 `assertGroupAccess(1)` 与 `assertGroupAccess(2)`
- 预期结果：同组通过；跨组抛出 `FORBIDDEN`；`ADMIN/PMO` 不受限
- 优先级：P1

### UT-19 登出后客户端 token 处理
- 关联需求/AC：AC-A1
- 被测对象：`AuthController.logout`
- 前置条件：已登录
- 输入：带 token 的 POST `/auth/logout`
- 步骤：1. 登出；2. 再次使用同一 token 访问 `/me`
- 预期结果：登出返回成功并写审计；无状态 JWT 在有效期内仍可解析（文档明确），前端清除 token；若实现黑名单则第二次 401
- 优先级：P2

### UT-20 登录失败不泄露账号是否存在
- 关联需求/AC：AC-A1；NFR 安全
- 被测对象：`AuthService.login`
- 前置条件：存在账号 `admin`，不存在 `nobody`
- 输入：`admin/wrong`、`nobody/any`
- 步骤：分别调用
- 预期结果：两者返回相同的 `AUTH_BAD_CREDENTIALS` 文案；响应时间差异不构成可观察侧信道（不做严格计时断言）
- 优先级：P2

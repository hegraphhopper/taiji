# 项目与申报书管理（PRD）

## Goal

让项目组以结构化方式提交自投项目申报书，让基金办和专家在同一份数据上完成形式审查与评审，并把附件正文转化为可用于重复度分析的文本。本任务是重复度引擎、趋势与决策的数据基础。

## 范围

- 项目主数据与申报书结构化内容：目标、研制内容、关键技术、节点计划、成员、预算、技术方向。
- 附件上传、文本解析、章节抽取与一键回填。
- 项目状态机、审批轨迹、专家评审记录。
- 项目列表检索、详情聚合、按角色数据范围过滤。
- 不做：重复度计算、趋势看板、投入分析、决策报告（后续子任务）。

## 功能需求

### F1 项目主数据

- 字段：名称、编码（自动生成 `TJJH-{年份}-{4 位序号}`，可手工覆盖且唯一）、基金类型、所属项目组、负责人、技术方向、预算（>0，两位小数）、起止日期（结束不早于开始）、摘要、预期成果。
- 创建时默认状态 `DRAFT`，记录创建人/时间；逻辑删除仅限草稿且无评审记录。
- 编码唯一性在服务层校验，冲突返回明确错误。

### F2 结构化申报内容

- 项目目标：多条文本，排序，至少 1 条。
- 研制内容：多条文本，排序，至少 1 条。
- 关键技术：名称 + 说明 + 难度（HIGH/MEDIUM/LOW），排序，可 0 条。
- 节点计划：阶段名、计划开始/结束、交付物、权重（0–100，合计建议 100），排序，至少 1 条。
- 项目成员：用户、角色（负责人/核心成员/参与人）、投入人月（>0）。
- 批量保存接口按项目整体替换子表，使用事务；任一校验失败整体回滚。
- 项目详情聚合返回上述全部内容，避免前端多次请求。

### F3 附件与解析

- 支持 `.docx`、`.pdf`、`.txt`、`.md`，单文件 ≤20MB；同一项目最多 10 个附件。
- 上传后保存元数据与文件；解析状态 `PENDING/PARSED/FAILED`。
- 自动解析：提取正文 → 按章节关键词切分 → 识别“项目目标/研制内容/关键技术/节点计划/考核指标” → 返回建议结构化内容。
- 一键回填：前端确认后调用批量保存；允许部分回填与人工修改。
- 重新解析、下载、删除（仅草稿/驳回状态）；解析失败展示原因。
- 解析正文入库，供重复度引擎直接使用；正文长度上限 200,000 字符。

### F4 基础状态流转（首版）

- 状态枚举保留完整集合：`DRAFT`、`SUBMITTED`、`REVIEWING`、`APPROVED`、`REJECTED`、`IN_PROGRESS`、`COMPLETED`、`TERMINATED`。
- 首版只启用最小闭环：`DRAFT → SUBMITTED → APPROVED / REJECTED`，由 `ADMIN`/`PMO` 操作；`SUBMITTED → DRAFT` 撤回仅限提交人。
- 每次转移写审批轨迹（from/to/action/operator/comment）与审计日志；非法转移返回 `400` + 错误码。
- 提交前校验：必填字段、至少 1 目标/1 研制内容/1 节点、预算合法；首次提交写入 `submit_time`。
- 移交 governance：形式审查、专家评分、多轮评审、立项/终止策略、按角色的完整动作权限。

### F5 检索与数据范围

- 列表筛选：关键词（名称/编码/负责人）、项目组、基金类型、技术方向、状态（多选）、预算区间、创建时间范围、重复度区间（读取快照，暂无则为空）。
- 排序：创建时间、预算、重复度、名称；分页。
- 首版 `ADMIN/PMO` 看全部；`GROUP_USER` 数据范围钩子接入但完整权限矩阵在 governance 验证。
- 详情、下载、删除均二次校验归属与角色。

### F6 页面

- 项目列表：筛选区、状态标签、预算/重复度列、提交/撤回操作。
- 新建/编辑：分步或分区表单（基本信息 → 目标/内容 → 关键技术 → 节点 → 成员 → 附件），支持保存草稿。
- 详情：Tab（概览、申报内容、节点与成员、附件、审批轨迹、重复度占位）。
- 首版不建专家评审页；审查/立项操作以管理员动作按钮呈现。
- 空态、加载态、错误态完整；保存前离开提示。

## 验收标准

- [ ] 项目组用户可创建草稿，完整填写全部结构化内容并保存；刷新后数据不丢失。
- [ ] 项目编码自动生成且唯一；手工重复编码被拒绝并提示。
- [ ] 上传 docx 申报书后解析成功，至少识别“项目目标、研制内容、关键技术”三段，并可一键回填。
- [ ] 上传 pdf/txt/md 均可解析；超过大小/类型限制被拒绝；解析失败有原因且可重试。
- [ ] 提交前缺目标/内容/节点时被拦截并定位到具体字段。
- [ ] 首版流程可走通：提交 → 管理员确认/驳回；审批轨迹完整。
- [ ] 非法流转（如 DRAFT 直接立项）返回 400；无权限用户尝试确认返回 403。
- [ ] 项目组用户无法查看/修改其他组项目（数据范围钩子生效）。
- [ ] 列表筛选与分页正确；删除草稿后列表不再出现。
- [ ] 所有写操作在审计日志可查。
- [ ] `mvn test` 覆盖基础状态流转、越权、解析器；`npm run build` 通过。

## 依赖与约束

- 前置：foundation（登录、鉴权基础设施、数据范围钩子、技术方向字典、审计写入）。
- 完整形式审查、专家评审、审批流移交 `fund-governance`。
- 解析仅支持文本层；扫描件 PDF 明确提示不支持。
- 附件存储目录 `storage/` 不进入 git；生产环境需持久化卷。
